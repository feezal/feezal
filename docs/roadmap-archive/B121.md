# B121 — Glass popups are not transparent — expected the cards' frost ✅ fixed
*Archived roadmap item — Bugs. Open items: [../ROADMAP.md](../ROADMAP.md) · Index: [README.md](README.md)*

**Reported (08/2026).** The details popups of the glass cards (light / climate / cover / fan / wled) rendered solid-looking. Expected: the frost the cards themselves have.

## None of the three hypotheses

The item listed backdrop-root containment first, and it is the right thing to suspect — a popup inside the card's shadow tree, under an ancestor that has its own `backdrop-filter`, would blur the card subtree instead of the page. But all five cards **already** promote `.details` to the top layer (`popover="manual"` + `showPopover()`), so that escape was in place. Not the tint being theme-heavy either, and not `degrade`.

Measured instead, over a hard red/blue striped view background — a working frost transmits the stripes as a smooth gradient, an opaque panel flattens them:

| | mean | spread (sd) |
|---|---|---|
| bare page | 55 | 78 |
| **card** frost (the target) | 143 | **42** |
| **popup**, as reported | 193 | **22** |
| popup with the `::backdrop` dim removed | 201 | 26 |

The popup *was* blurring — sd 22, not 0 — and removing the modal dim barely moved it, which ruled out the wash being the cause. What the numbers said was simpler: the popup transmitted **30%** of the page where the card transmitted **65%**.

## The fallbacks had diverged

Both rules read the same variable. Their fallbacks did not:

```css
.card    { background: var(--feezal-glass-tint, rgba(255,255,255,0.35)); }
.details { background: var(--feezal-glass-tint, rgba(255,255,255,0.7));  }   /* ← */
```

A theme that sets `--feezal-glass-tint` made card and popup agree, which is why this was never seen on a themed site — with no theme the popup fell back to **twice** the card's opacity, and at 70% white the frost has almost nothing left to show. (`--feezal-glass-solid`, the degrade path, had drifted the same way: 0.97 against the card's 0.94.)

One number each. After: popup mean 142 / sd 41 against the card's 143 / 42 — the same frost, as the item asked for. With the deliberate `::backdrop` dim back in place it reads 123/28, which is the modal treatment doing its job rather than the frost failing.

**Verified** in [glass-popup-frost.test.js](../../www/test-e2e/glass-popup-frost.test.js), which pins both halves: the popup's computed background and blur must **equal the card's** (the assertion that would have caught the drift, and that keeps holding once a theme supplies the variable), and it must transmit as much of the striped page as the card does — measured from real screenshots, since `backdrop-filter` has no computed-style answer to "did it blur anything". The top-layer promotion is asserted too: it is not the cause here, but it is what would silently break the frost again. Reverting the tint fails both.

**Relates:** the glass family (E58/E106 shared chrome), E155 (the popup centring rework), B61 (glass backdrop-filter repaint quirks).
