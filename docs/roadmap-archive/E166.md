# E166 — Link element for the device-card families (`glass/metro/circle/eink-link`) ✅ done
*Archived roadmap item — Element Ecosystem. Open items: [../ROADMAP.md](../ROADMAP.md) · Index: [README.md](README.md)*

**Requested (08/2026).** A link card in each of the four device-card families — one tap opens a URL. One behaviour contract, chrome per family.

## One controller, four views

`@feezal/feezal-controller-link` is the E137 shape applied to a non-device function: `linkAttributes` (the shared fragment — `href`, `subscribe` + `message-property` for the dynamic target, `open`, `image`), `LINK_CONSUMED_ATTRIBUTES` for the parity suite, and `LinkController` owning everything that is not chrome. `icon`/`label` stay per family (their conventions differ — metro's come from `MetroTileBase.tileAttributes`), which is the same split the contact fragment settled. No discovery fragment: a link is not a device, nothing announces it.

The **popup chrome is exported from the controller package too** (`linkPopup()` + `linkPopupStyles`) — it is deliberately identical across families, like the behaviour, so it lives with the behaviour rather than being copied four times.

Decisions inside `activate()`, each with its reason:

- **One editor guard for four families.** The tap entry point checks `feezal.isEditor` once, in the controller — a canvas tap selects, never navigates, and no family can forget the guard.
- **`#/view` routes in place, whatever the open mode** (N30): a popup or new tab of your own app's view is never what that link means. Routed via `feezal.site.view` (the B23-approved entry — drives updateVisibility + hash sync). Only when the view actually **exists**: an unknown `#hash` falls through to ordinary navigation, so an anchor link on some page is not swallowed by the router.
- **`new-tab` is `noopener,noreferrer`** — the target must not get a handle on the dashboard.
- **Unknown `open` values degrade to same-tab** rather than throwing, so the select stays extensible (the roadmap names a later kiosk-window mode) and an old element under a newer saved site keeps working.

## The popup's embedding fallback is an affordance, not a detection

Sites that forbid embedding (`X-Frame-Options` / CSP `frame-ancestors`) **cannot be detected from here** — the iframe fires `load` either way and cross-origin documents are opaque. So the "cannot be embedded" fallback the item asked for is a *permanent* "Open in tab ↗" link in the popup header, sitting directly above whatever error page the browser paints into the blocked frame. Top-layer promotion follows the basic-camera precedent (`popover="manual"` + `showPopover()`, fixed+z-index as the no-popover fallback); ✕ and Esc close, and the Esc document listener is released on close *and* on host disconnect (the N42 leak class — a popup must not leave a listener behind when its element is deleted mid-open).

## The four views

Thin by construction — each renders a face (image wins over icon, per the item), a label, the family's availability badge, and delegates the tap: **glass** frost card (wide 2:1 layout goes horizontal, E105), **metro** accent tile (front-only — a link has no flip back side; image fills the tile), **circle** disc with the label below (the family's footprint, without the arc machinery a static button does not need), **eink** 1-bit panel with the E57 render-signature dedup.

Packages follow the observed conventions rather than the documented ones where they diverge: version **3.0.0** (the element-package lockstep major — server/www 5.0.0 are the app packages), and **no sibling `@feezal/*` dependencies declared** (workspace-resolved; A32 governs third-party deps only — checked against glass-contact, which declares none either).

**Verified** in `test-browser/feezal-element-link.test.js`: the modes, the editor guard, dynamic href incl. `message-property` and live rewire, internal routing incl. the unknown-hash fall-through, the popup (embed src, permanent open-in-tab affordance, ✕/Esc, Esc-listener teardown on detach) — plus a per-family smoke that every face tap goes through the one controller and every family swaps icon for image. The E137 parity suite asserts the declared contract for all four.

**Relates:** E137 (the discipline this follows), basic-camera (popup + dynamic-src precedents), basic-navigation / N30 (the `#/view` overlap), U45 (palette).
