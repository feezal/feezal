# U80 — Generate wizard: the App generator always creates a new site (name → deploy → viewer link) ✅ done
*Archived roadmap item — Editor UX. Open items: [../ROADMAP.md](../ROADMAP.md) · Index: [README.md](README.md)*

**Requested & done (07/2026).** The **App** generator now always builds onto a **new site**, so the user's current site is never touched:

1. **Name first.** Clicking the App tile opens a **new-site name** step, prefilled with the next free **`siteN`** (`site1`, `site2`, … — computed from `/api/sites`). *Create & continue* `POST`s the site with `fromSite: <current>` (inheriting the MQTT broker connection — A-earlier work) and **switches the editor to it** (`window.location.href = /editor/?/<name>/`); a duplicate (409) or a `/`-containing name errors in place without navigating.
2. **Resume on the new site.** After the reload, `loadViews` (feezal-sidebar-inspector) sees the `sessionStorage['feezal:generateAppSite']` flag matches the just-loaded site, clears it, and calls the generate dialog's `resumeNewSiteApp()` — which opens the wizard straight at the **App setup** (axis + family) in an auto-deploy mode. The new site inherited the connection, so discovery is ready.
3. **Auto-deploy.** When the wizard's `_generateApp` finishes on the new site, the auto-flow calls `feezal.app._deploy()` so the app is published immediately.
4. **Viewer link.** The result screen shows a **prominent "Open <site> in the viewer"** button (`/viewer/<site>/`, new tab) + an Export hint.

The chosen approach was **Switch to the new site** (user decision) — it reuses the existing site-switch + deploy machinery rather than building off-screen, so it's the lower-risk path; the one reload is early (right after naming) and everything after — wizard, generate, deploy, the viewer-link dialog — runs on the new site. The **Devices** tile is unchanged (adds to the current view). The `window.location.href` navigation is behind a `_navigateTo` seam for tests.

**Ships with:** the new-site name step + `_nextSiteName` / `_confirmNewSite` / `resumeNewSiteApp` / `_navigateTo` in `feezal-generate-dialog.js`, the auto-deploy hook, the prominent viewer link on the result screen, the `loadViews` resume hook in `feezal-sidebar-inspector.js`, browser tests (siteN default, the name prompt, POST-with-fromSite + resume flag + navigation, duplicate error, resume opens at App setup in auto-deploy mode, auto-deploy + viewer link), and a `docs/TESTING.md` line.

**Relates:** **U58** ✅ / **U67**–**U79** ✅ (the App generator this fronts), the site-manager's create + `fromSite` MQTT inheritance (the create path reused), `feezal-app-editor._deploy` / `_view` (the auto-deploy + `/viewer/<site>/` URL), **U73** ✅ (the welcome-tour autogenerate path still drives `_chooseApp` directly, bypassing the new-site prompt).
