# E142 — Dialog `label` attribute: editor-only placeholder tag to tell dialogs apart
*Archived roadmap item — Element ecosystem. Open items: [../ROADMAP.md](../ROADMAP.md) · Index: [README.md](README.md)*

**✅ Done (07/2026).** Dialogs are invisible ~120×40 px canvas pseudo-elements; several on one view all rendered the identical "Dialog" chip and were impossible to tell apart. They now show a disambiguating placeholder — **editor-only, never rendered in the viewer.**

**Shared helper** (in `@feezal/feezal-element`), so the wording can't drift across the 11 dialog packages:
- `dialogLabelAttribute` — the `label` attribute descriptor (`{name:'label', type:'string', default:'', help:'…never shown in the viewer — unlike "title"…'}`).
- `dialogPlaceholderLabel(base, label)` — `` `${base}: ${label}` `` when set, else the base word.

**Two behaviours (refined during implementation):**
- **`*-dialog` and `*-countdown-dialog`** (material / glass / eink / paper — 7 elements) gain the editor-only **`label`** attribute. The canvas placeholder reads "Dialog: Confirm delete" / "Countdown Dialog: Reboot"; empty → just the base word. `label` is a reflected Lit property (persists with the site), rendered only inside the `feezal.isEditor` placeholder branch — the viewer render never includes it.
- **`*-dialog-view`** (material / glass / eink / paper — 4 elements) deliberately do **NOT** get a `label` — a dialog-view already references a view, so its identity is that view. Its placeholder shows the **bound view name**: "Dialog: &lt;view name&gt;" (from the existing `view` attribute; empty view → just "Dialog"). *(This replaced the roadmap's original "give every dialog a label" plan — the dialog-view's disambiguator is the view it renders, requested during implementation.)*

**Distinct from `title`.** Dialogs already have a `title` attribute that IS the user-visible heading. `label` is the opposite — never user-visible, editor-only. The inspector help spells out the difference so authors don't reach for `title` to organise their canvas.

**Ships with:** the shared helper + the `label` wiring on the 7 label-bearing dialogs and the `view`-name placeholder on the 4 dialog-views; patch bumps on every touched package; a browser test (`test-browser/feezal-dialog-label.test.js`: helper behaviour, per-element placeholder text, viewer-leak check, and that dialog-views expose no `label`); one stale "Dialog View" placeholder assertion updated to "Dialog: popup"; TESTING.md note.

**Relates:** the dialog element set (material/glass/eink/paper × dialog / dialog-view / countdown-dialog), E114 (parity — the attribute/behaviour is identical across the family), the dialog `title` attribute (the user-visible counterpart), pseudo-element editor conventions (other invisible placeholders could reuse the same editor-label idea later).
