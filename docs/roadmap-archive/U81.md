**Requested & done (07/2026).** A dedicated **first-run broker-setup dialog** (`feezal-connect-dialog`) now runs **before** the welcome tour whenever the site has **no broker host** configured — the very first thing a new user sees. It is the same connection form as the Connection sidebar, but **larger and in a modal**, and it is **skippable**.

- **Trigger.** `feezal-app-editor._maybeFirstRunSetup` (replacing the direct `_maybeAutoStartTour` call ~800 ms after connect) reads the Connection sidebar's `connection` (host, or the hostname parsed from its `uri`). No host → open the connect dialog; the welcome tour starts only once the dialog fires `feezal-connect-closed` (saved **or** skipped). A host already set → straight to the tour. With no host it re-appears on every open (nagging but skippable); once a host is saved it never shows.
- **Form.** Protocol (ws/wss/mqtt/mqtts), Host, Port (per-protocol placeholder), Username/Password, and a **Viewer connection** switch. Larger fonts/inputs than the sidebar.
- **Guidance baked in** (product decisions): recommends **ws:// / wss://** (browsers speak only WebSocket MQTT); **DIRECT is the default + recommended** viewer mode; the Direct/Bridge switch is **disabled and forced to bridge for mqtt://|mqtts://** (a browser can't open those); a page served over **https://** warns that a direct viewer must use **wss://** (browsers block ws:// there); **wss://** warns that each viewing **device must trust the broker's TLS certificate** (direct) or that the **feezal server** must trust it via the sidebar CA (bridge).
- **Save.** Writes the built connection onto the Connection sidebar and calls `feezal.app._deploy(done)` (deploy persists it and connects the server bridge); a spinner shows while deploying, then the dialog closes. **Skip for now** closes without saving.
- **Tour cleanup.** The welcome tour's broker steps — **`broker` (connect broker)**, **`broker-status` (connection status)** and **`deploy` (deploy to apply the connection)** — were **removed** from `feezal-welcome-tour.js` (they were the shared post-fork steps; none remain). The Explore path's `finish` and the Autogenerate path's `finale` still cover Deploy, and the Autogenerate path now goes fork → **discovery-wait** directly.
