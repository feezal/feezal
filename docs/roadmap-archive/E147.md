# E147 — AI-on-the-edge meter element (glass / metro / circle): value + rate + action/status + error
*Archived roadmap item — Element ecosystem. Open items: [../ROADMAP.md](../ROADMAP.md) · Index: [README.md](README.md)*

**✅ Done (07/2026).** [E146](E146.md) makes an AI-on-the-edge meter *discoverable* — but only as a plain value sensor (all its HA discovery exposes). The device publishes a much richer set a generic readout throws away: the consumption **rate**, the current processing **action/status**, the **error** state, `raw`/`pre`, and the **last-reading timestamp**. A dedicated **meter card** surfaces all of it, built in **glass, metro and circle** over a shared controller. It is deliberately **generic** — at heart a meter card (value + rate + reading-age + fault), serving any MQTT meter, with a JSON convenience for the AI-on-the-edge case.

**Controller — `@feezal/feezal-controller-aiedge` (E137).** The three families are views over one controller (config read from host attributes). Two wiring modes:
- **JSON** (`subscribe-json`): AI-on-the-edge's `…/<seq>/json` bundles `{value, raw, pre, error, rate, timestamp}` (quoted strings) — one topic, each field read via a key path (`message-property-value`/`-rate`/`-error`/`-timestamp`/`-raw`, defaulting to `payload.value` etc.). A stringified JSON payload is parsed first.
- **Separate** (`subscribe-value` [+ `subscribe-rate`]): plain value/rate topics for any other meter (payload IS the value).

Plus `subscribe-status` (current step / last action) and availability from the base (N31, the device's `…/connection`). State: `value`/`rate`/`raw`/`status`/`error`/`timestamp`; getters `faulted` (error ≠ "no error"), `stale` (last reading older than `stale-after` seconds), `age` (compact relative time — refreshed by a 20 s heartbeat so it stays live without new messages). Helpers `formatMeterValue` / `relativeTime` are exported and shared by the views.

**Views** (`feezal-element-{glass,metro,circle}-meter`): prominent value + unit, a rate line (↗ + `rate-unit`), the action/status line, an error badge (`--error-color`, text in a tooltip) when faulted, the last-reading age (turns error-colour with ⚠ when stale), an availability badge, and `raw` on a `show-raw` toggle (plus `show-rate`/`show-status`/`show-timestamp`). Metro puts value+rate on the front and status/age/raw on the flip back.

**A robustness fix surfaced during build:** a view that reflects the fragment's `message-property-*` attributes with an empty default would stamp `message-property-value=""` and blank the field path. The controller's `_attr` now treats an **empty attribute as unset** (→ use the default), so every family (whether or not it declares those attributes as reflected properties) reads the right paths. Caught by the browser test — metro-meter failed all three fields until this fix.

**Ships with:** the `feezal-controller-aiedge` package + glass/metro/circle views; `www/package.json` registration (controller + 3 elements) + regenerated `generate-elements` manifest; the E137 parity test (all three views declare the full `AIEDGE_CONSUMED_ATTRIBUTES`); a controller unit test (`test/feezal-controller-aiedge.test.js`) and a functional browser test driving a real json message through each view (`test-browser/feezal-meter-cards.test.js`); the element-smoke suite mounts all three; a TESTING.md §6 row.

**Deferred (noted, not blocking):** the optional inline **sparkline** for the rate (reuse E30) and an **AI-on-the-edge-aware discovery helper** that derives the sibling json/status/connection topics from a discovered value topic (strip `/value` → base) to pre-wire the card — a small convenience, not a dependency. eink/material views can follow later (E114 parity).

**Relates:** [E146](E146.md) (discovery of the value sensor — this element shows the rest), E137 (controller-first for the 3-family function), E114 (parity — glass/metro/circle now, eink/material later), E30 (sparkline for the rate), N31 (availability from `connection`), the pure-MQTT principle, U58 (a future Generate step could place these from discovered meters).
