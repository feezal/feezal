# B105 — Source formatting: line break inside closing tags, glued closing-tag runs ✅ fixed
*Archived roadmap item — Bugs. Open items: [../ROADMAP.md](../ROADMAP.md) · Index: [README.md](README.md)*

**Reported (08/2026).** The formatted site HTML (deploy + the N15 source view, both through `/api/format`) produced a line break INSIDE a closing tag, with the `>` hugging the next opening tag and no break between closing tags:

```html
           subscribe-availability='…'></feezal-element-glass-light></feezal-view
    ><feezal-view
```

**Root cause:** prettier's HTML printer with the default `htmlWhitespaceSensitivity: "css"`. Custom elements have no known CSS display, so prettier treats them as **inline** and refuses to introduce whitespace around their tags — the hugging-bracket construction *is* prettier preserving whitespace-exactness.

## Why neither obvious option was right on its own

Both candidates were measured against a realistic site rather than argued from the docs:

- **`htmlWhitespaceSensitivity: "ignore"`** fixes the reported shape completely — closing tags on their own lines, no hugging brackets, a stable fixed point, and attribute formatting (one per line past `printWidth`) untouched. But it also reflows **text content**, and reflowing inline markup that has *no* whitespace between its parts changes what renders: `<b>bold</b>glued<i>italic</i>` becomes three lines, which the browser collapses to `bold glued italic` — spaces that were not there before. Confirmed by comparing collapsed text, not assumed.
- **A pure post-pass** over the `"css"` output would have to unwrap broken closing tags *and* re-indent everything that moved — which is writing an HTML pretty-printer to work around the one being used.

**Shipped:** `"ignore"` for structure, with `<template>` bodies shielded. Template contents are stamped into the DOM verbatim, so whitespace there is user content, not formatting: each body is lifted out behind an opaque token before formatting and restored byte-for-byte afterwards. The restore uses a replacement *function*, so `$&` / `$1` sequences inside user markup are never expanded.

**Verified** in `server/test/format-html.test.js` (12 new): no line break inside a closing tag, no hugging bracket, every closing tag alone on its line, no glued closing runs, one attribute per line preserved, nesting indented, and the format → format fixed point — plus the template guarantees (tight inline markup untouched, a body preserved byte-for-byte including its own indentation, several templates not crossed over, no token left behind, `$`-sequences safe, fixed point with templates present).

**Relates:** N15 (source view — the visible consumer), the deploy path (`socket hub`) which persists this formatting into `views.html`.
