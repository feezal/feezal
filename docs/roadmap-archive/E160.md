# E160 — Stamp a device-class-appropriate icon on value and gauge cards ✅
*Archived roadmap item — Element Ecosystem. Open items: [../ROADMAP.md](../ROADMAP.md) · Index: [README.md](README.md)*

**✅ Implemented (07/2026) — scope corrected during build.** A shared `NUMERIC_SENSOR_ICONS` table (`@feezal/feezal-element/feezal-numeric-sensor-icons.js`, the numeric sibling of `feezal-sensor-types.js`, every name verified against the installed Material Symbols set) is stamped via `device_class: {attr: 'icon', valueMap: NUMERIC_SENSOR_ICONS}`. **Only `circle-value` and `glass-value` actually render an `icon`** — the other value cards (eink/metro/panel/tui) and *all* gauges have no icon attribute (a gauge is a dial), so the entry's "six value + five gauge" scope was wrong; stamping them would target a non-existent attribute. `basic-icon-value` is excluded too (its `icon` is an 11-variant family base, not a plain glyph). `glass-value`'s hardcoded `thermostat` default → neutral `sensors` (attribute default + constructor + render fallback) — a deliberate cosmetic change: an unset manually-placed glass-value now shows `sensors`, not a misleading thermometer. Table re-exported from `feezal-discovery-fragments.js` (one import line per card). Tests: `test/feezal-numeric-sensor-icons.test.js`. Patches: feezal-element 3.0.18, circle-value 3.2.6, glass-value 3.0.13.

**Reported (07/2026):** every discovered `*-value` card shows a **temperature** icon. Pressure, CO₂ equivalent, VOC, PM2.5 and humidity should each get a fitting one.
