# U95 — View inspector: Conditions and MQTT tabs for views ✅ done
*Archived roadmap item — Editor UX. Open items: [../ROADMAP.md](../ROADMAP.md) · Index: [README.md](README.md)*

**Requested (08/2026).** Selecting a view showed only Attributes/Styles. The Conditions and MQTT tabs were gated on a predicate that required a `feezal-element-*` tag, and behind that gate sat a bigger gap: `feezal-view` did not run the E50 conditions machinery at all, and had no MQTT wiring of its own for an MQTT tab to report. Built in four commits, the tab gate deliberately last so nothing ever showed an empty panel.

## 0. Visibility on views — decided against, and enforced

Views do **not** get the show/hide actions. A hidden view is not a `display:none`: it would have to disappear from layout-app drawer entries, basic-navigation tabs and swipe order, and refuse direct routing by falling through to the first visible view. Anything less leaves navigation pointing at something that is not there, and that reach is not worth the one use case.

It is enforced in **two** places on purpose. `VIEW_CONDITION_ACTIONS` restricts the engine, so a hand-edited `conditions` attribute (source mode, an import, an AI edit) cannot reintroduce the rejected state; the inspector filters the same list, so the action is never offered in the first place. A row that arrives anyway is flagged in the panel rather than silently ignored — the select would otherwise render blank with no explanation.

## 1a. `getProperty` lifted to module scope — an extraction first

Found while scoping, and it changed the build order. `FeezalConditions` reads a payload via `host.getProperty(msg, row.property)` and falls back to plain `msg.payload` when the host has no such method — so a view without one would silently ignore `property` and never match a condition on a nested JSON payload. Worse than no feature, and invisible.

But `getProperty` was not a helper: it was an instance method on `FeezalElement` depending on `this.split()`, a non-trivial bracket/quote path parser. Both were lifted to module scope in `feezal-element.js` with the class methods delegating (the N41 pattern), so the view shares ONE implementation instead of growing a second, subtly different path parser.

## 1b. The engine on `feezal-view`

A `conditions` attribute, a `FeezalConditions` instance built with the restricted action list, `getProperty()` delegating to the shared function, and connect/disconnect on the lifecycle points elements use — including `connectedCallback`, because a view switch detaches and re-attaches the node without any property changing. No new bundle weight: the viewer already carried `feezal-conditions.js` for elements.

## 2. `subscribe-theme` — what gives the MQTT tab something to list

The U51 per-view theme, until now static, becomes MQTT-settable. Payload is a theme name in either spelling the Theme control accepts (bare suffix or full `feezal-theme-*` class); `''` **and** `default` clear back to the site theme — the same vocabulary the site-level `theme` control command (E91) already uses, so knowing one is knowing the other.

Two decisions worth keeping:

- **The editor gate sits inside the callback, not before the subscribe.** The topic is wired either way, which is what lets the U88 MQTT tab show live traffic — the panel's whole point — but the value is not applied while "prevent MQTT element manipulation" is on, because `theme` REFLECTS and a broker value would otherwise be written into the saved views.html. Turning the setting off gives live theming on the canvas, exactly as it does for elements.
- **Wiring is idempotent per topic.** `connectedCallback` and the first `updated()` both wire; a retained message is delivered to the handle that existed when it arrived, so a churning resubscribe would drop it.

The view keeps the same `_subscriptions` registry an element's base class does — real handles only — which is precisely what the MQTT panel reads.

## 3. The tab gate, widened last

`_singleElementSelected` gained a sibling `_singleViewSelected`, and both tabs plus the U88 fall-back-to-Attributes rule now key on one `_wiringTarget` predicate, so the tabs and the fallback can never disagree. The fallback additionally watches `viewSelected`, since the gate now depends on it. The MQTT panel dropped its explicit `FEEZAL-VIEW` exclusion — it was there because a view wired nothing — and its empty/note text speaks view vocabulary when a view is selected.

The e2e case that asserted the tabs *vanish* on a view was rewritten to the new contract; the fall-back rule is still exercised by the multi-selection case, which is the shape that would otherwise leave `sl-tab-group` pointing at a missing panel.

**Verified** by reverting each guard and watching the matching test fail: without the idempotence check the subscribe-once test fails, without the editor gate the prevent-MQTT test fails. Plus unit coverage for the filtered action list, the per-selection default row (a view starts on `class`, an element still on `hide`), the flagged unrunnable row, the intro copy, and the MQTT panel reporting on a view.
