# U111 — *-link elements: comfortable view picking for internal link targets ✅ done
*Archived roadmap item — Editor UX. Open items: [../ROADMAP.md](../ROADMAP.md) · Index: [README.md](README.md)*

**Requested (08/2026).** The link family (E166: glass/metro/circle/eink
`-link`) already routes `#/view` hrefs in place
(`feezal-controller-link` — `href` is a plain `type: 'string'`
attribute), but AUTHORING an internal link means hand-typing `#/viewname`
into a text field. Offer a convenient view picker instead.

**Direction (refine at implementation):** upgrade the shared `href`
descriptor to a dedicated inspector control (new attribute `type:
'linkTarget'` in the generic attributes panel, or a `viewPicker: true`
flag on the string descriptor) rendering:
- a **mode toggle URL / View** (derived from the current value — a
  `#/…` href selects View mode);
- View mode = a dropdown of the site's views (same source as the other
  view pickers) writing `#/<view>` back into `href`; include layout-app
  sub-view paths (`#/<appview>/<section>/<page>`, U103) — at least the
  plain views, ideally the shell's routable paths;
- URL mode = today's free text input.
One control in the generic panel serves ALL four families at once (the
link elements use the generic inspector — no per-family work). The
declared attribute stays `href` with unchanged semantics — saved
dashboards and the dynamic-href topic override are untouched.

**Caveats:** B128 applies — view names with spaces must survive the
picker (encode `sl-option` values or use the B128 shared helper once it
lands); the picker must list views of the CURRENT site live (views
created after the inspector rendered — refresh on open like the other
pickers).

**Relates:** E166 (link family + `#/view` routing), B128 (spaces in
sl-select values), U103 (nested routable paths), U47 (create-view
sentinel pattern, if "create new view" is wanted here too).

## Implemented (08/2026)

The first suggested route: the shared `href` descriptor
(`linkAttributes` in `@feezal/feezal-controller-link`) is now
`type: 'linkTarget'`, and the GENERIC attribute panel renders a dedicated
control for that type — one implementation serves all four link families
at once, no per-family work, and any future element can opt in by
declaring the type.

- **Mode toggle URL / View**, derived from the value (`#/…` selects View);
  a manual toggle overrides the derivation per item and is cleared on
  selection change so it never leaks across elements.
- **View mode** = an `sl-select` over `_linkTargets()`: every view name
  PLUS each layout-app shell view's routable nested paths
  (`shell/leaf`, the N30 `view/embedded` form, read from the app's
  `items`), computed live from the site on each render so new views are
  offered. Picking writes `#/<view>` back into `href`. B128's
  encode/decode helpers wrap the option values, so spaced view names
  round-trip.
- **URL mode** = the plain text input, exactly as before.
- The attribute stays `href` with unchanged semantics — saved dashboards
  and the dynamic-href topic override untouched (the link controller
  behaviour did not change at all; the 26-test link suite stayed green
  unmodified).

5 browser tests (`test-browser/u111-link-target.test.js`): mode
derivation both ways, spaced-name selection (B128), pick-writes-`#/view`,
the layout-app sub-path listing, and the manual toggle. Reverting the
descriptor to `type: 'string'` fails all five (probed).
