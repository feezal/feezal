# E148 — `eink-number` → `eink-value`: numeric-card naming parity
*Archived roadmap item — Element ecosystem. Open items: [../ROADMAP.md](../ROADMAP.md) · Index: [README.md](README.md)*

**✅ Done (07/2026).** The eink family's numeric readout card was `eink-number` while every other styled family used `-value` (`circle-value`, `glass-value`, `metro-value`, `tui-value`). E138 established the `-value` convention and parked eink as a documented gap; this closes it. `basic-number` stays the unstyled primitive that keeps its name.

**Hard rename (no aliasing — E138/E130 precedent):** `feezal-element-eink-number` → `feezal-element-eink-value`; palette name `Number` → `Value`; class `FeezalElementEinkValue`; the editor placeholder word `Number` → `Value`. Behaviour, attributes, discovery (`component: 'sensor'`) and chrome are unchanged.

**Rename mechanics applied:**
- package dir + `package.json` name/main + tag + class renamed; version bumped to 3.1.0.
- `www/package.json` dependency updated (kept alphabetical: `…-eink-switch`, `-eink-value`, `-eink-wled`).
- `npm install` re-linked the workspace symlink; `node scripts/generate-elements.js` regenerated `www/editor/feezal-elements.js` (now imports `eink-value`); the stale `extraneous` `eink-number` entry pruned from `package-lock.json`.
- **Family-switcher alias removed.** `feezal-sidebar-inspector.js` carried `FN_ALIAS = {number: 'value'}` purely for this one divergence — now emptied (`{}`), so `eink-value` pairs with the other `-value` cards by its shared `value` function with no alias, and `basic-number` (the primitive) is correctly **not** paired with the styled value cards.
- `feezal-switch-family.test.js` updated (import/refs → `eink-value`; the "number↔value divergence" test reframed as a normal same-function pairing).
- `docs/BREAKING-CHANGES.md`: migration-table row `eink-number → eink-value` added; the stale "eink keeps `eink-number`" family-gap note corrected.
- `docs/TESTING.md`: eink family + E115 switch-family + E138 taxonomy rows updated to `eink-value`.

**Breaking:** saved dashboards using `feezal-element-eink-number` break — the user fix is a source-view search-replace `eink-number` → `eink-value` (bundle with the next breaking release). No reused-name hazard (unlike E138's glass/metro `-sensor` reuse, `eink-number` is retired, not repurposed).

**Verification:** production build clean; the element-smoke suite mounts `eink-value`; the switch-family suite pairs `glass-value ↔ eink-value`.

**Relates:** E138 (established `-value`, documented this exact gap), E114 (numeric-card parity across families), E115 (family switch — needs the consistent function name), E132 (the earlier `-sensor`→numeric rename wave this finishes), `basic-number` (the primitive that keeps its name — the distinction being made).
