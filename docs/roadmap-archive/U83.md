# U83 — Alignment & distribution tools for multi-selection ✅ done
*Archived roadmap item — Editor UX. Open items: [../ROADMAP.md](../ROADMAP.md) · Index: [README.md](README.md)*

**✅ Implemented (08/2026).** A context submenu on a multi-selection: align 6 ways to the selection bounds, distribute horizontally/vertically (≥3 elements, outermost anchored), match width/height/size to the FIRST selected element. The geometry lives in a pure module (`www/src/feezal-canvas-align.js`) that returns only the boxes that change, so an operation that would move nothing reports "Already aligned" instead of dirtying the site. Reads RENDERED boxes (an element sized by a class or preset still lines up), skips locked elements and reports the count, and takes ONE undo snapshot per operation. Absent for a single element and on flow views. Phase-2 equal-gap smart guides during drag remain unimplemented — see the note below. Tests: `test/feezal-canvas-align.test.js`, `test-e2e/align-layers.test.js`.

**Found by audit (08/2026): none exist** — no align-left/center/right/top/middle/bottom, no distribute, no match-size (searched inspector/styles/app-editor). With edge-snapping and multi-select already solid, this is the biggest remaining canvas gap for tidy dashboards.
- Context-menu group + small floating toolbar when ≥2 elements are selected: align 6 ways (to selection bounds; to view with one selected), distribute horizontally/vertically (equal gaps), match width/height/both.
- One undo snapshot per operation; respects locked elements (skip, report count).
- 💡 phase 2: equal-gap smart guides during drag (the snap engine at `_snap()` already computes sibling edges — extending it to equal-spacing hints is incremental).
