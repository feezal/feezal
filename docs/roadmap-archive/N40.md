# N40 — Lazy view subscriptions: subscribe a view's topics only when it is first shown ✅ done
*Archived roadmap item — Near-term Improvements. Open items: [../ROADMAP.md](../ROADMAP.md) · Index: [README.md](README.md)*

**Done (07/2026).** Shipped as its **own** setting with the same shape as N37 pause (as requested), not folded into the pause switch:
- **Site attribute** `lazy-view-subscriptions` (a switch in Site Settings → Viewer → Bandwidth) + **per-view** `lazy-subscriptions="inherit|always|never"` (a view attribute, in the inspector) — mirroring `pause-hidden-subscriptions` / `pause-subscriptions`.
- **Mechanism (approach a, with b as fallback).** `FeezalVisibility` gained `_effectiveLazy(view)` + a `_seen` set: a view that has **never been visible** and is lazy-effective is paused **immediately** (`_pauseNow`, no grace). Crucially the controller is now constructed in **`feezal-site.connectedCallback`** — *before* the site's view elements upgrade — so those elements hit the existing `isPaused` precondition in `FeezalElement.connectedCallback` and **skip the initial subscribe entirely** (truly never subscribe). If elements ever connect first (unusual boot order / static export), the immediate `_pauseNow` still unsubscribes them (the approach-b fallback). `feezal-app-viewer` keeps a late fallback construction guarded by `!feezal.visibility`.
- **Composition with N37.** Lazy (defer the first subscribe) and pause (drop on a later hide) are orthogonal and compose: both on → fully on-demand; lazy only → warm after first show; pause only → the plain N37 behaviour. `never` opts a view out of both; the active view at load always subscribes eagerly.
- Browser-tested (`test-browser/feezal-visibility.test.js`): immediate initial pause, first-reveal subscribe + stay-warm, `never` eager, `always` defers, N37 composition, and the true-lazy controller-first case (an element in a hidden lazy view never subscribes until shown). Config surfaces + a `docs/TESTING.md` block under N37.

**Requested (07/2026).** A view's topics should be subscribed the first time the view becomes visible — not on load. Today, even with [N37](N37.md) ✅'s hidden-view pausing on, **every** view subscribes on load and the hidden ones pause only *after* the grace timer (default 30 s). So a dashboard with twenty views floods the broker with all twenty views' subscriptions at startup, and a view the user never opens still subscribes for at least the grace window. Lazy fixes both: an initially-hidden view **never subscribes until first revealed**, and one never visited never subscribes at all.

**This extends [N37](N37.md) ✅, reusing its machinery.** The `isPaused(el)` precondition already gates `FeezalElement.addSubscription`, and `resumeSubscriptions()` already re-wires a view on reveal (with the [B40](B40.md) ✅ retained-cache repaint). The only new part is the **initial** state: a hidden view under an effective pause policy must be marked paused **before its elements' `connectedCallback` runs**, so they skip the first subscribe instead of subscribing-then-unsubscribing.

**Caveats (mostly handled by N37 already).** Retained values repaint on reveal via the B40 cache, so a lazy view opens showing the last-seen state, not blank. A view with **non-retained** data shows nothing until its first message *after* reveal — the same trade-off N37's pause already makes; `never` opts such a view out. The active view at boot (and `never` views) always subscribe eagerly.

**Relates:** **[N37](N37.md)** ✅ (the pause/resume machinery + `isPaused` precondition this extends), **[B40](B40.md)** ✅ (retained cache → the reveal repaint), **A18** (kiosk / wall tablets — the beneficiary), `feezal-visibility.js` / `feezal-site.js` (boot order), `FeezalElement.addSubscription` (the gate).
