# N40 — Lazy view subscriptions: subscribe a view's topics only when it is first shown ✅ done
*Archived roadmap item — Near-term Improvements. Open items: [../ROADMAP.md](../ROADMAP.md) · Index: [README.md](README.md)*

**Debugging (07/2026).** MQTT/lazy tracing is available in the viewer console for investigating subscription behaviour. Enable with `window.feezalDebugMqtt = true` (this session) or `localStorage['feezal:debug-mqtt'] = '1'` (persists; reload). It logs **every subscribe/unsubscribe** (`[mqtt] SUB/UNSUB <topic>`, marking whether it actually opened/closed the broker subscription vs. an added/removed local subscriber), the **per-view lazy/pause decisions** on each `update()` (`[lazy] view "<name>": …`), and each element's **connect → subscribe / SKIP (view paused) / pause / resume** with its view + topic. Wired in `feezal-connection.js` (`mqttDebugOn` / `window.feezalMqttDebugOn`), `feezal-visibility.js` (`_dbg`), and `feezal-element` (`_lazyLog`); off by default.

**Fixes (07/2026) — "subscribed but never shown".** The trace surfaced two real gaps that let hidden/lazy views keep their subscriptions:
1. **The Polymer base (`feezal-polymer-element`) had no pause support at all** — no `__n37Paused`, no `pauseSubscriptions`/`resumeSubscriptions`. The paper-* elements (badge/button/checkbox/dropdown/listbox/slider/switch/tabs) use this base, so the controller's `el.pauseSubscriptions?.()` was a silent no-op and they **stayed subscribed on hidden/lazy views**. Added the full pause contract to the Polymer base, mirroring `FeezalElement` (connect-time `isPaused` skip, `addSubscription`/`_subscribe` gates, pause/resume via the reconnect cycle).
2. **The base `_subscribe()` / `_subscribeAvailability()` did not gate on `__n37Paused`.** `addSubscription` was gated, but the primary subscribe could be reached AFTER a pause — Lit's `updated()` on a `visible` change, a controller card's `rewire`, or a second `_subscribe` on a property update (with `_subscribed` reset to `false` by the pause's `_unsubscribe`) — silently **re-opening** a hidden view's topics. Added the pause gate to both (both bases).
3. Belt-and-suspenders: `feezal-site` builds the visibility controller **only when its `<feezal-view>` children are present**, deferring to `DOMContentLoaded` for a boot order (inline-defined static export) where the element upgrades during parsing before its children exist. (The normal module-script viewer already has the views at that point, so this is behaviour-neutral there.)

**Fixes (07/2026) — layout-app embedded sub-views.** The console trace on a `layout-app` app surfaced two more issues:
4. **Subscribe → unsubscribe → subscribe churn.** `layout-app._embed(force)` re-cloned the **same** already-mounted sub-view when `_embed(true)` fired several times on init (`items` + `activeView` in `updated()`, plus N30 hash routing) — each `content.replaceChildren(clone)` tore down the live clone (disconnecting its elements → unsubscribe) and rebuilt it. It now **skips a redundant re-embed of the same mounted view** (`name === this._mounted && content.firstElementChild`); `force` no longer re-clones an already-shown view (the source is immutable in the viewer). The clone now subscribes **once**.
5. **A sub-view template double-subscribed with its visible clone.** A `layout-app`/`layout-view` sub-view is shown only as a CLONE inside the router; its top-level `feezal-view` is a `display:none` **template** that never renders — but the visibility controller only paused it if a lazy/pause policy happened to apply, so otherwise its elements subscribed in parallel with the clone. The controller now **always pauses** a view whose name appears in a router's sub-views (`_embeddedViewNames`, read from the routers' serialized `items`/`view` attributes so it works at build time), independent of the lazy/pause config. So the template never subscribes; only the visible clone does. (This is why such a view logs as "hidden": the top-level instance genuinely is — the visible one is the clone.)

**Done (07/2026).** Shipped as its **own** setting with the same shape as N37 pause (as requested), not folded into the pause switch:
- **Site attribute** `lazy-view-subscriptions` (a switch in Site Settings → Viewer → Bandwidth) + **per-view** `lazy-subscriptions="inherit|always|never"` (a view attribute, in the inspector) — mirroring `pause-hidden-subscriptions` / `pause-subscriptions`.
- **Mechanism (approach a, with b as fallback).** `FeezalVisibility` gained `_effectiveLazy(view)` + a `_seen` set: a view that has **never been visible** and is lazy-effective is paused **immediately** (`_pauseNow`, no grace). Crucially the controller is now constructed in **`feezal-site.connectedCallback`** — *before* the site's view elements upgrade — so those elements hit the existing `isPaused` precondition in `FeezalElement.connectedCallback` and **skip the initial subscribe entirely** (truly never subscribe). If elements ever connect first (unusual boot order / static export), the immediate `_pauseNow` still unsubscribes them (the approach-b fallback). `feezal-app-viewer` keeps a late fallback construction guarded by `!feezal.visibility`.
- **Composition with N37.** Lazy (defer the first subscribe) and pause (drop on a later hide) are orthogonal and compose: both on → fully on-demand; lazy only → warm after first show; pause only → the plain N37 behaviour. `never` opts a view out of both; the active view at load always subscribes eagerly.
- Browser-tested (`test-browser/feezal-visibility.test.js`): immediate initial pause, first-reveal subscribe + stay-warm, `never` eager, `always` defers, N37 composition, and the true-lazy controller-first case (an element in a hidden lazy view never subscribes until shown). Config surfaces + a `docs/TESTING.md` block under N37.

**Requested (07/2026).** A view's topics should be subscribed the first time the view becomes visible — not on load. Today, even with [N37](N37.md) ✅'s hidden-view pausing on, **every** view subscribes on load and the hidden ones pause only *after* the grace timer (default 30 s). So a dashboard with twenty views floods the broker with all twenty views' subscriptions at startup, and a view the user never opens still subscribes for at least the grace window. Lazy fixes both: an initially-hidden view **never subscribes until first revealed**, and one never visited never subscribes at all.

**This extends [N37](N37.md) ✅, reusing its machinery.** The `isPaused(el)` precondition already gates `FeezalElement.addSubscription`, and `resumeSubscriptions()` already re-wires a view on reveal (with the [B40](B40.md) ✅ retained-cache repaint). The only new part is the **initial** state: a hidden view under an effective pause policy must be marked paused **before its elements' `connectedCallback` runs**, so they skip the first subscribe instead of subscribing-then-unsubscribing.

**Caveats (mostly handled by N37 already).** Retained values repaint on reveal via the B40 cache, so a lazy view opens showing the last-seen state, not blank. A view with **non-retained** data shows nothing until its first message *after* reveal — the same trade-off N37's pause already makes; `never` opts such a view out. The active view at boot (and `never` views) always subscribe eagerly.

**Relates:** **[N37](N37.md)** ✅ (the pause/resume machinery + `isPaused` precondition this extends), **[B40](B40.md)** ✅ (retained cache → the reveal repaint), **A18** (kiosk / wall tablets — the beneficiary), `feezal-visibility.js` / `feezal-site.js` (boot order), `FeezalElement.addSubscription` (the gate).
