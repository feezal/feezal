# B94 — Generate review: room-move dropdown leaves a stale value on the row beneath ✅ fixed
*Archived roadmap item — Bugs. Open items: [../ROADMAP.md](../ROADMAP.md) · Index: [README.md](README.md)*

**Reported (07/2026).** In the autogeneration **review** dialog, changing a device's room via its dropdown (which moves the device to another bucket) leaves the **device beneath it** — the one that shifts up into the vacated slot — showing the **wrong** dropdown value: the room the first device was just moved to.

**Root cause — unkeyed list reuse + Lit's `.value` dirty-check.** The review rows were rendered with a plain `b.entities.map(e => …)` (no stable key), so Lit reuses `<select>` DOM nodes **by position**. When the user picks a new room, the native `<select>` value is set (e.g. `Kitchen → Living room`) and `_reassign` re-renders. The moved device leaves the bucket, the device beneath shifts up into its DOM slot, and Lit reuses the **first device's `<select>` node** (whose DOM value the user just changed to *Living room*) for it. Its `.value="${b.label}"` binding is now `Kitchen`, but Lit's dirty-check compares against the node's **last committed** value — also `Kitchen` (the moved device's original bucket) — so `Kitchen === Kitchen`, Lit skips the DOM write, and the user's stale *Living room* value stays visible on the wrong row.

**Fix.** Key the review list so DOM nodes track their entity, not their position: `repeat(buckets, b => b.label, …)` for the buckets and `repeat(b.entities, e => e.__key, …)` for the rows. The moved device's stale node is discarded (its key leaves the source bucket) and a fresh node is created in the target bucket; the device beneath keeps its own node, whose value was never touched. No `.value`/dirty-check change needed once nodes stop being reused across entities.

**Fixed (07/2026):** `repeat` keys on both the bucket and entity maps in `_renderReview` (`feezal-generate-dialog.js`). Browser-tested — moving the top device of a room leaves the row beneath reading its own room (the test fails on the pre-fix `.map()`, asserting `'Living room'` where `'Kitchen'` is expected).
