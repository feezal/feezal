# E158 — Slider discovery: climate setpoint + cover/blind level axes ✅ done
*Archived roadmap item — Element ecosystem. Open items: [../ROADMAP.md](../ROADMAP.md) · Index: [README.md](README.md)*

**✅ Done (07/2026)** in `@feezal/feezal-element/feezal-discovery-fragments.js`, landed on top of [E157](E157.md) and [B81](B81.md) over one clean fragment as the entry asked.

**A cover needs two variants, not one.** The entry names the HA spelling (`set_position_topic` / `position_topic` / `position_open` / `position_closed`), but the Homematic recognizer emits feezal's **separate-mode** spelling (`position_command_topic` / `position_state_topic` / `position_min` / `position_max`) — confirmed in `server/src/mqtt/recognizers/homematic.js`, and the cover controller's own map consumes both. Wiring only the HA keys would have missed the item's own acceptance case (the Homematic blind). Both dialects ship.

Both publish a **plain number**, so neither uses B81's `publish-json-key`: Homematic's `position_command_topic` takes a LEVEL, and HA's `set_position_topic` is a dedicated topic whose default template is the bare position (z2m spells it `…/set/position`). Asserted structurally, not just observed.

Homematic's LEVEL range (0…1) comes from `position_min`/`position_max` rather than being assumed 0–100 — as the entry required.

**Climate** needed only one variant: Homematic and HA agree on `temperature_command_topic` / `min_temp` / `max_temp` / `temp_step`. **`water_heater` rides along** (not in the entry): E150 established it as climate-shaped with identically-named keys, so excluding it would have been a fresh parity gap for one line's saving.

**`panel-knob` came along too.** The entry left this conditional on E157's consolidation; E157 did consolidate, so the axes were factored into a shared `settableAxes` array that the knob and `sliderDiscovery` both build on — the knob still keeping its own `number` map. A knob is a natural thermostat dial.

**Tests:** in `www/test/feezal-discovery-settable-axes.test.js` — both cover dialects, the Homematic range, setpoint wiring, `water_heater`, and every exclusion the guardrail promises (read-only climate, open/close-only blind, report-only cover). Plus a structural check that **every** axis variant carries a `when` guard, so a future axis cannot be added ungated.

---

Extend the E156 slider←axis crossing to two more settable numeric axes a `*-slider` should offer but currently doesn't:
- **Climate setpoint** — a Homematic thermostat / TRV (and any HA `climate`) exposes a settable target temperature (`temperature_command_topic` / `temperature_state_topic`, `min_temp`/`max_temp`/`temp_step`). A slider should offer it as "*<thermostat>* setpoint", wiring value + range + step.
- **Cover / blind level** — a Homematic blind actuator (and any HA `cover` with position) exposes a settable position 0–100 (`set_position_topic` / `position_topic`, `position_open`/`position_closed`). A slider should offer it as "*<blind>* position".

**Mechanism:** the same `discovery.accepts` + `when(config)` + per-axis rows E156 built (extended by E157) — add `climate` and `cover` accepted components to `sliderDiscovery` with axis variants keyed on the settable topic (`temperature_command_topic`, `set_position_topic`). One entity → one slider row each; label suffix per U56.

**Guardrail (inherited):** settable-only. A `climate` with no settable setpoint, or a `cover` that reports position but has no `set_position_topic` (open/close-only blind), yields **no** slider row — never offer a read-only value. Homematic scale notes: blind LEVEL is 0–1 on the wire (position range maps to the slider's min/max like the existing brightness scaling); climate setpoint uses the discovered `min_temp`/`max_temp`/`temp_step`.

**Ships with:** the `climate` + `cover` accept variants on `sliderDiscovery` (+ `panel-knob` if E157 has consolidated it onto the shared fragment), mapping tests (Homematic TRV → slider setpoint with right range/step; Homematic blind → slider position 0–100; open/close-only cover and read-only climate **excluded**), TESTING.md discovery rows, version bumps per policy.
