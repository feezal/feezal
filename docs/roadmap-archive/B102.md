# B102 — U85 toasts ignore the editor dark mode ✅ fixed
*Archived roadmap item — Bugs. Open items: [../ROADMAP.md](../ROADMAP.md) · Index: [README.md](README.md)*

**Reported (08/2026).** The editor's toast notifications (U85 — e.g. the "Deployed" toast after a successful deploy) rendered light in a dark editor.

**Root cause:** `feezal-toast` correctly consumes the editor palette (`--feezal-bg`, `--feezal-color`, `--feezal-btn-hover`) with light fallbacks — but the tag was **missing from the `:host(.dark)` propagation list** in `feezal-app-editor.js`, so in dark mode the values were never supplied and the `#fff` fallback won. Exactly the shape the connection-lost overlay had before it: the component is dark-ready, the shell never feeds it.

**Fix:** one line — `feezal-toast` added to the dark propagation selector list. Verified live: the toast card computes `rgb(46, 46, 46)` in a dark editor instead of white.

## The ratchet matters more than the fix

This is the third instance of the same failure, so the fix that counts is the one that makes a fourth impossible. N43's chrome-adoption ratchet does **not** catch it — that guard covers Shoelace (`sl-*`) chrome, not the `--feezal-*` palette contract, which is precisely why this slipped through a codebase that already has a dark-mode ratchet.

`www/test/editor-dark-palette-propagation.test.js` closes that half: it scans `www/src` for components reading `--feezal-bg/-bg-sub/-color/-btn-hover` **with a fallback**, extracts every tag each file defines, and asserts each is either named in the editor's `:host(.dark)` list or documented in one of two allowlists —
- `INHERITS`, for components that always render inside a host that *is* on the list (custom properties inherit through the shadow tree), each naming that host;
- `LEGACY_UNAUDITED`, seeded with the five pre-existing offenders found when the ratchet was written, so the gate could start blocking **new** misses immediately instead of waiting for a full sweep.

A third test rejects stale allowlist entries, and a fourth asserts the scan itself still matches something — a ratchet that silently stops finding anything is worse than none. Verified by reverting the one-line fix: the gate fails both specifically (`feezal-toast is fed the palette`) and generically (listed under missing components).

**Still open, deliberately:** the five `LEGACY_UNAUDITED` entries (`feezal-pwa-icon-dialog`, `feezal-sidebar-clients`, `feezal-sidebar-color-ranges`, `feezal-template-editor`, `feezal-welcome-tour`). Each is either a real dark-mode bug of this shape or an undocumented inheritance; they were captured rather than guessed at.
