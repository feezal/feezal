# E182 — echo2mqtt discovery + the media-element capability gaps (mute, provider, dedupe) ✅ shipped
*Archived roadmap item — Elements. Open items: [../ROADMAP.md](../ROADMAP.md) · Index: [README.md](README.md)*

**Requested (08/2026).** [echo2mqtt](https://github.com/hobbyquaker/echo2mqtt)
(new interface, same maintainer) bridges Amazon Echo devices to MQTT. The
media elements should **autodiscover** those devices and offer the full
transport: prev / play / pause / next, volume **and mute**, repeat and
shuffle, album art, and artist / song / album / provider — where **album
and provider are shown only once when they carry the same text**.

**The echo2mqtt contract (from its README):**
- status `echo/status/<device>/…` (retained): `audioPlayerState`
  (`PLAYING`/`PAUSED`/`IDLE`/`INTERRUPTED`/`FINISHED`), `volume` (0-100),
  `isMuted` (`ON`/`OFF`), `title`, `artist`, `album`, `provider`,
  `imageUrl`, plus a combined `media` JSON
  (`{state,title,artist,album,provider,imageUrl,mediaId}`) and a
  non-retained `progress` JSON (`{progress,length}` in ms).
- commands `echo/set/<device>/…`: `play`, `pause`, `next`, `previous`,
  `shuffle` (`on`/`off`), `repeat` (`on`/`off`), `volume` (0-100),
  `isMuted` (`ON`/`OFF`), `playerState` (`PLAYING`/`PAUSED`).
- device roster: `echo/status/bridge/devices` (JSON list with name,
  topic, serial, type, capabilities) — the natural discovery source,
  exactly like the Frigate stats roster.

**Why a NATIVE recognizer is required (not the HA-discovery path):**
echo2mqtt can publish HA discovery configs (`--ha-discovery`), but HA
MQTT discovery has **no `media_player` component** — the bridge
necessarily fans a device out into separate sensors, buttons, switches
and a number entity. Feeding that into feezal would generate a pile of
unrelated cards, never one media card. So this needs a recognizer in
`server/src/mqtt/recognizers/` (alongside `frigate.js`, `wled.js`,
`evcc.js`) that reads the bridge roster (or the `echo/status/+/…` tree),
synthesizes **one media entity per device**, and stamps the whole
attribute set in one pick. Source badge: "Echo".

**Capability gaps in the media elements (verified in code — these must
land WITH the recognizer, or discovery cannot stamp them):**
- **No mute at all.** `circle-media` / `metro-media` have volume,
  shuffle and repeat, but nothing for mute (the only `mute` hits in the
  source are the `--feezal-media-muted-color` style token). Add
  `subscribe-mute` / `message-property-mute` / `publish-mute` plus
  payload knobs (echo2mqtt speaks `ON`/`OFF`, others `true`/`false`) and
  a mute button in the volume row.
- **No provider field.** Add `subscribe-provider` /
  `message-property-provider` and render it as the source line.
- **Album/provider dedupe (the requested rule):** when the resolved
  album and provider strings are equal (trimmed, case-insensitive),
  render only ONE of them. Suggested precedence: show the album (the
  more specific label) and drop the duplicated provider; a `show-album`
  / `show-provider` pair still gates each independently. Pure display
  logic, unit-testable.
- **Repeat is a tri-state in feezal** (`off`/`all`/`one`) but a boolean
  for echo2mqtt (`on`/`off`): the recognizer must stamp payload mappings
  so the cycle degrades to two states, or the element needs a
  `repeat-mode: cycle | toggle` knob. Decide at implementation.

**Wiring efficiency:** every field could be stamped onto the SAME
combined `media` JSON topic with different `message-property` paths
(`payload.title`, `payload.artist`, …) instead of five separate topics.
The elements currently open one subscription per `subscribe-*`, so
either dedupe subscriptions by topic (the multivalue controller already
does this) or stamp the individual retained topics. Prefer the combined
topic + subscription dedupe: fewer retained reads, one atomic update.

**Also worth stamping (out of scope for v1, note in the entry):**
`progress` gives position/length for the seek bar (ms, non-retained,
max. every 10 s — the elements expect seconds), and
`echo/status/<device>/connected` is a natural availability topic (N31).

**Relates:** E183 (glass-media — the new family view), the media elements
(circle/metro), the native recognizers (frigate/wled/evcc precedent),
E161/E165 (device grouping + one-pick fill), N31 (availability).

---

**Shipped (08/2026).** The capability gaps and the recognizer landed
together, on a new shared controller rather than in one element:

- **`@feezal/feezal-controller-media`** (E137 architecture) now owns the
  whole media contract: `mediaAttributes` (the ~40 topic/payload
  descriptors incl. the new **mute** quartet, **provider**, `label`,
  `command-mode`, `repeat-mode`, `time-unit`), the wiring, value
  coercion, the transport/volume/mute/shuffle/repeat publishing and
  `mediaDiscoveryMap`. **Subscriptions are deduped per topic**, so the
  combined-JSON wiring opens exactly ONE subscription (verified in the
  browser suite) instead of five retained reads.
- **`albumProviderLines()`** implements the requested rule: when album
  and provider match (trimmed, case-insensitive) only one line renders —
  the album wins as the more specific label; the per-field show toggles
  still gate each independently.
- **Two command shapes** solve the echo2mqtt mismatch cleanly:
  `command-mode: payload` (one topic + a payload per action, the
  pre-existing behaviour and still the default) and `command-mode:
  topic` (the action name becomes the last topic segment —
  `echo/set/<device>/next`). Repeat gained `repeat-mode: cycle | toggle`
  for bridges that only know boolean repeat.
- **circle-media migrated** onto the controller (its CSS is untouched;
  the ~40 attributes are now derived from the fragment, so a new knob
  cannot be forgotten) and gained the mute button, the provider line and
  the optional `label` header.
- **`server/src/mqtt/recognizers/alexa.js`** (renamed with the bridge:
  echo2mqtt became alexa-remote-mqtt, whose default topic prefix changed
  from `echo` to `alexa` — so the prefix is NOT hardcoded: both defaults
  are recognized and a custom one is learned from its
  `<prefix>/status/bridge/devices` roster, with the discovery id kept
  prefix-independent so re-prefixing cannot duplicate a card) synthesizes one `media`
  entity per Echo from the bridge roster or any per-device
  media/state/volume message, stamping every metadata field onto the one
  combined topic, topic-mode transport, ON/OFF mute, toggle repeat and
  availability from `connected`. Registered in the recognizer list.
  Roster note: the framework's `parsePayload()` intentionally yields
  objects only, so the JSON-ARRAY roster is read from the extracted
  value instead.

Tests: 12 unit (`test/feezal-controller-media.test.js`), 8 server
(`server/test/native-discovery-alexa.test.js`), 21 browser
(`test-browser/feezal-media.test.js`, shared with E183). Full suites
green. **metro-media deliberately stays on its thinner tile contract**
(front/back flip, no album/provider surface) — migrating it is a
follow-up, not a blocker.
