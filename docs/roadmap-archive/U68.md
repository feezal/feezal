# U68 — Device-list selection: refined range-select + drag-select (reusable) ✅ done
*Archived roadmap item — Usability & UX. Open items: [../ROADMAP.md](../ROADMAP.md) · Index: [README.md](README.md)*

**✅ Done (07/2026).** The Generate wizard's checkbox selection is now a reusable behaviour ([`src/feezal-range-select.js`](../../www/src/feezal-range-select.js), class `RangeSelect`) shared by the Devices list and the App **review** list (U69):

- **A plain press is always a plain toggle** of that row, and becomes the range anchor.
- **Shift+press applies the pressed row's toggle RESULT to the whole range** between the anchor and it — checks the span when the pressed row turns on, clears it when it turns off (across group boundaries). The anchor is kept, so a second Shift+press moves the endpoint.
- **Shift+press with no anchor extends from the pressed row UPWARD** until the first row already in that state (a select-up-to-the-boundary fill).
- **Press-and-drag** paints the pressed row's action onto every row the pointer crosses (mouse/pointer via `renderRoot.elementFromPoint` on `pointermove`; the list is `user-select:none` so nothing text-selects; the window listeners are torn down on `pointerup` and `disconnectedCallback`).

`RangeSelect` owns the anchor/range/drag bookkeeping and is fed the host's selection `Set` (read via `selection()`, written as a NEW set via `commit()` so Lit re-renders) plus the visible ordered key list per press (which differs by list/stage). Both lists wire `@pointerdown → _selPress`. Browser-tested: target-action range, both directions, the boundary fill, and drag paint (`test-browser/feezal-generate-dialog.test.js`, `describe('U68 …')`).

**Relates:** the earlier Shift+click this refined (its anchor-state model became the target-action model), **U69** (the review list that shares it), **U58** / **U67** ✅ (the wizard), `feezal-generate-dialog.js` (`_selPress` / `_endDrag` / `_currentOrder`).
