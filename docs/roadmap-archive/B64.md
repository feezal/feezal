# B64 — `*-switch` autodiscovery misses multi-output HmIP switch actuators (virtual-receiver grouping wrong for switches)
*Archived roadmap item — Bugs. Open items: [../ROADMAP.md](../ROADMAP.md) · Index: [README.md](README.md)*

**✅ Fixed (07/2026)** in `server/src/mqtt/native-discovery.js` (+ `server/test/native-discovery.test.js`).

**Symptom.** HmIP switching actuators (channelType `SWITCH_VIRTUAL_RECEIVER`) were not auto-discovered as `*-switch`. Reporter's device: a `HmIP-MOD-OC8` (8-output open-collector module) whose output "Steckdosen Werkstatt" at `channelIndex 14` — a clearly-named socket — simply vanished from discovery.

**Root cause.** `hmipVirtualGroup` grouped a device's virtual-receiver channels in **position-based chunks of 3** (`groupIndex = floor(pos/3)`, `leader = vr[groupIndex*3]`), which misaligns whenever the channels don't start at a clean multiple of three. On the OC8 the named output landed under a *different*, unnamed leader, whose name failed the switch name-word gate → the whole group was dropped. (The name-word heuristic was NOT the cause — "Steckdosen Werkstatt" contains "steckdose".)

**Fix.** The real HmIP layout (confirmed against RedMatic-HomeKit's per-device tables) is: each output = a `*_TRANSMITTER` channel followed by three consecutive `*_VIRTUAL_RECEIVER` channels; the output is the first VR (`transmitter+1`). The transmitter is a *different* channelType, so its index gap splits the virtual receivers into **one consecutive-index run per output**. `hmipVirtualGroup` now takes the **first channel of each run** as the output — device-agnostic, absorbing each device's base index and the step-4 block layout (RedMatic-HomeKit: DRBLI4 base 2, DRSI4 base 6, OC8 base 10) with no per-device table. Applied uniformly to cover (`BLIND_`), light (`DIMMER_`), and switch (`SWITCH_VIRTUAL_RECEIVER`).

Two supporting fixes:
- **Stable discovery id** keyed on the leader's `channelIndex` (`…:c14`) instead of a run ordinal (`…:g0`) — retained bursts arrive name-sorted, so an ordinal shifts and silently drops outputs.
- **Read-time stale-group filter** — drops any grouped entity whose leader is no longer a genuine run-leader (a same-type channel exists at `leaderIndex-1`), eliminating duplicates from out-of-order arrival.

Regression test added (OC8 multi-output → one switch per output, custom names win); the unrealistic *consecutive*-channel cover/dimmer fixtures were corrected to transmitter-gap layouts. Full server suite green.
