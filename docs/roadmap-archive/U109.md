# U109 — Views: copy/cut/paste + "copy to another site" ✅ done
*Archived roadmap item — Editor UX. Open items: [../ROADMAP.md](../ROADMAP.md) · Index: [README.md](README.md)*

**Requested (08/2026).** Whole-view clipboard operations:

1. **Copy / Cut / Paste for views** — via the view context menu (canvas +
   layers tree + footer selector) and the standard shortcuts when a VIEW
   is the selection target. Copy serializes the whole `<feezal-view>`
   (elements, inline styles, name, theme, conditions attributes); paste
   creates it as a NEW hidden view with a deduped name (`-copy`
   numbering, as duplicate); cut = copy + delete (one undo step each).
   Reuse the element clipboard's mechanism where it fits (B31 light-DOM
   survival, component instances via their template reference) — paste of
   a view whose component definitions do not exist on the target site
   must carry the definitions along or warn.
2. **"Copy to another site…" context-menu entry** — submenu/dialog
   listing the other sites (from `/api/sites`); picking one serializes
   the view and inserts it into that site's saved markup server-side
   (deduped name there too). The target site gets the view on its next
   editor load / deploy; component definitions and any referenced assets
   are the open question — v1 may copy the view markup only and surface a
   warning listing missing components/assets on the target. Cross-site
   copy must NOT auto-deploy the target site.

**Relates:** B126 (duplicate-view fix — same hidden-on-create + dedupe
semantics), B31 (clipboard light-DOM), U32 (component definitions),
sites API (`/api/sites`).

## Implemented (08/2026)

**① Copy / Cut / Paste for views.**
- `_serializeView` = the element clipboard's own mechanism on a whole view:
  `_clone` (B31 deep clone, light-DOM survives) + `_clean` (editor classes,
  z-index junk, identifying-attribute order), display stripped so the
  serialized form is neutral.
- Menu paths (`_copyView`/`_cutView`/`_pasteViewFromClipboard`) live on the
  editor shell and write BOTH the internal `_clipboardTpl` and the system
  clipboard — a view travels between editor instances (and thus between
  sites) as plain markup. Reading falls back to the internal clipboard
  where `navigator.clipboard.readText` is not permitted.
- Keyboard: with the VIEW as the selection target, the native copy event
  already serialized it (selectedElems = the view); the paste handler now
  recognizes a `<feezal-view` payload and routes it to `_pasteViewHtml`,
  and Ctrl+X takes a view branch (copy + dialog-free `_removeView`, one
  undo step). `_pasteInternal` guards against a copied view being pasted
  INTO a view.
- Paste = the B126/duplicate semantics: deduped name (kept when free, else
  `-copy` numbering via `_nextView`), landed hidden, navigated to,
  interact.js rebound, one snapshot.
- Surfaces: the tab-bar view context menu (Copy/Cut/Paste view) and the
  layers tree's view-header menu (delegating to the same editor methods).
  The FOOTER shows a status echo, not a menu — there was nothing to extend
  there; skipped deliberately.

**② "Copy to site…"** — `POST /api/sites/:name/views` inserts the fragment
before `</feezal-site>` in the target's SAVED markup (wrapping an empty
site), dedupes the name against the target, and does NOT deploy anything.
v1 copies the view markup only, exactly as scoped: the response lists
component definitions the target lacks (`<feezal-component>` instances vs
`<template feezal-component>` defs) and foreign site-asset references
(`/assets/<other-site>/…`; global assets pass) — the editor surfaces both
in a warning toast. The context menu's "Copy to site" flyout lists the
other sites from `/api/sites`, fetched when the menu opens.

**Verified:** 5 supertest cases (`server/test/api-view-copy.test.js`):
fragment validation, insert + free-name keep, `-copy`/`-copy1` dedupe,
missing-component and foreign-asset reporting. 3 e2e cases in
`test-e2e/editor-flows.test.js` (20 green): menu copy→paste (deduped,
exactly one visible view, content travelled), cut→paste round-trip under
the original name, and cross-site copy landing in the other site's
site.html while the source keeps its view. Neutering `_pasteViewHtml`
flips the paste cases red (probed).
