# E167 — `glass-camera`: basic-camera in the glass frame ✅ done
*Archived roadmap item — Element Ecosystem. Open items: [../ROADMAP.md](../ROADMAP.md) · Index: [README.md](README.md)*

**Requested (08/2026).** A glass-family camera card that is deliberately
minimal: **basic-camera plus the glass border style with rounded edges** —
nothing more.

**Design:** `feezal-element-glass-camera` **subclasses
`FeezalElementBasicCamera`** (own package depending on
`@feezal/feezal-element-basic-camera`, A32 rules) and overrides ONLY:
- `palette` → category Glass (glass colours/icon);
- `styles` → the frost card frame around the feed: the family's rounded
  squircle corners + border, `--feezal-glass-tint` frame surface and the
  usual glass style knobs; the FEED itself stays untouched (no blur over the
  video — the frame is glass, the picture is the picture). `degrade`
  inherits meaning for the frame only.
Everything else — every attribute, mqtt-image, chips, events, popups,
buttons, discovery (camera component + Frigate keys) — is inherited
unchanged; zero behaviour duplication. E115 then pairs `camera` across
basic ↔ glass for family switching automatically.

**Ships with:** package + manifest regeneration, E115 pairing sanity check,
a small browser test (renders the feed inside the glass frame; inherited
mqtt-image path works through the subclass), TESTING.md §6 row, patch bump.

**Relates:** E163 ✅ (basic-camera — the base class), the glass family
chrome (`glassCardStyles`), E115 (family switch pairing), A32 (dependency
declaration in the element package).

## Implemented (08/2026)

Exactly the design: `@feezal/feezal-element-glass-camera` (3.0.0, declares
its `@feezal/feezal-element-basic-camera` dependency per A32) subclasses
`FeezalElementBasicCamera` and overrides only:

- **palette** → Glass / the family colour, same `videocam` icon;
- **styles** → the frost frame ON THE HOST (family radius + tint + blur +
  border + a `--feezal-glass-frame` ring width) with the feed's `.stage`
  clipped to the inner radius — the blur/tint sit on the frame ring and any
  letterbox area, never over the picture; `degrade` (new attribute, family
  meaning) swaps the frame blur for the solid, feed untouched. The base
  `border-radius` and `--feezal-camera-bg-color` knobs are dropped (the
  frame owns both); every other base style knob stays.

Everything else — the full descriptor including discovery (camera component
+ Frigate keys) — is spread from the base: zero behaviour duplication, and
the mqtt-image path demonstrably runs through the subclass. E115 pairing is
automatic by function suffix and asserted both ways; a consequence worth
knowing: app generation in the GLASS family now resolves `glass-camera`
(the cross-family basic-camera fallback keeps covering metro/eink/…).

4 browser tests (`test-browser/feezal-element-glass-camera.test.js`):
subclass + descriptor inheritance (attributes superset, discovery keys,
dropped/added style knobs), mqtt-image through the subclass inside the
frame with the frame/picture split pinned, degrade, E115 both directions.
Frame CSS revert-probed. Full node (1601) + browser (1678) suites green.
