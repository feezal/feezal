# B70 — System element editor placeholders: swipe shows text not icon, mismatched chrome, inconsistent default sizes
*Archived roadmap item — Bugs. Open items: [../ROADMAP.md](../ROADMAP.md) · Index: [README.md](README.md)*

**✅ Fixed (07/2026).** Three inconsistencies in the **System** pseudo-element editor placeholders, all addressed:

1. **`system-swipe` showed the word "swipe" instead of the icon.** Its placeholder rendered `<span class="material-icons">swipe</span>`, whose `.material-icons` rule was missing `font-family` (the global class can't reach shadow DOM). Switched to `<feezal-icon name="swipe">` — the shadow-safe path (same fix as the device-health board).
2. **`system-swipe`'s placeholder chrome differed** — it hardcoded `background: #eceff1; border/color: #455a64`. Aligned its `.ph` to the shared System placeholder chrome: `color: var(--secondary-text-color, #777)`, `border: 2px dashed var(--feezal-border, #bbb)`, no opaque background.
3. **Default sizes were inconsistent** (140×40 / 120×40). Set `defaultStyle: {width: '160px', height: '40px'}` on **every** System element — `system-notification`, `-pin`, `-script`, `-splash`, `-swipe`, and added one to `system-connection-status` (which had none).

**Ships with:** the three fixes, patch-bumps on all six touched packages, and browser assertions in `test-browser/feezal-system-swipe.test.js` (placeholder renders a `feezal-icon`, not `.material-icons` text; default size is 160×40).

**Relates:** the device-health icon fix (the identical shadow-DOM `.material-icons` → `feezal-icon` fix), E7 (`system-swipe` origin), the System element family (the shared placeholder chrome + default-size convention this unified).
