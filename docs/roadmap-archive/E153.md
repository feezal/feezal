# E153 — `metro-loadpoint`: move the overloaded front controls to a 2×2 backside ✅ done
*Archived roadmap item — Element ecosystem. Open items: [../ROADMAP.md](../ROADMAP.md) · Index: [README.md](README.md)*

**✅ Done (07/2026)** in `www/packages/@feezal/feezal-element-metro-loadpoint/`.

The four charge-mode buttons (Off / Solar / Min+Solar / Fast) moved off the front's cramped inline row onto `renderBack()` as a **2×2 grid** (`display: grid; grid-template-columns: 1fr 1fr`) with full `.mbtn` touch targets — the `metro-lock` backside pattern. The **front** keeps the readout only: charging status, big charge power and the vehicle SoC → limit line (the heating loadpoint's reduced °C view is unchanged). The ⋯ flip affordance was already there, since `renderBack()` has always returned content.

The backside's existing detail rows (session energy, vehicle title/range, min/max current, phases) stay below the grid: the grid is `flex: 0 0 auto` so it is never squeezed, the detail list takes what is left. On 4x2-and-wider tiles `MetroTileBase`'s existing container query puts the grid and the detail list side by side.

**Shipped with:** the browser test in `www/test-browser/feezal-loadpoint-cards.test.js` (front carries no mode buttons; the back grid is two columns with the four modes in order; a back button publishes the mode and the active one is marked; ⋯ flips) and the `docs/TESTING.md` E109 row.

---

The `metro-loadpoint` **front is overloaded** — the charge-mode buttons (Off / Solar / Min+Solar / Fast) sit inline under power + vehicle SoC/limit ([metro-loadpoint.js:79-80,123-126](../www/packages/@feezal/feezal-element-metro-loadpoint/feezal-element-metro-loadpoint.js#L79)), a cramped row of tiny targets on a Metro tile. It already extends `MetroTileBase` (which provides the flip/backside), so: **move the four mode buttons to the backside as a 2×2 grid, bigger** (touch-friendly), via `renderBack()` — exactly like `metro-lock`'s back buttons. The **front** keeps the primary readout (power + SoC/limit + charging state); the ⋯ flip affordance appears automatically once `renderBack()` returns content. Ships with a browser test (front shows power/SoC, backside 2×2 has the four modes and `setMode` publishes) and a TESTING.md row; version bump.

**Relates:** `metro-lock` (the backside-buttons pattern to mirror), `MetroTileBase` (`renderFront`/`renderBack`/flip — the mechanism), E109 (the evcc loadpoint family this refines), glass-loadpoint (the sibling that had the same overload — see **B68**), **B69** (glass-meter overload — same "declutter into the popup/backside" theme).
