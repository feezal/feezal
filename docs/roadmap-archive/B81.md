# B81 — Slider discovery offers Homematic dimmers but not zigbee2mqtt light brightness/CT ✅ fixed
*Archived roadmap item — Bugs. Open items: [../ROADMAP.md](../ROADMAP.md) · Index: [README.md](README.md)*

**✅ Fixed (07/2026)** in `@feezal/feezal-element/feezal-discovery-fragments.js`, `feezal-element.js`, and the 3 sliders + `panel-knob`.

**The entry's fix was not implementable as written.** It says the map variant should wire "json payload mode" on the slider — but **no slider or knob had one**: all four published a bare number (`pub(topic, String(value))`). Diagnosis was right, remedy assumed a capability that did not exist. So the fix is an element change plus a map change:

- **`publish-json-key`** (new shared attribute + `numericPublishPayload()` in `feezal-element.js`, wired into `material-slider`, `carbon-slider`, `paper-slider`, `panel-knob`). Empty → the previous bare-number behaviour, byte for byte. Set → `{"<key>": value}`. Presence IS the mode; no enum, because a single-value control needs exactly one key — unlike the light/cover controllers, whose `payload-mode` + `json-map` pair has a whole object to describe.
- The value stays **numeric** in the JSON. `{"brightness":"128"}` is rejected by z2m, so the quotes are load-bearing and are asserted.
- **Two new axis variants** gated on `schema: 'json'` + a brightness/CT capability. The read side needed no new machinery — the state topic already carries the object, so `message-property: payload.brightness` points into it.

**Range defaults matter more than expected.** A JSON light that declares no `brightness_scale` would have inherited the control's own 0–100 default and silently capped the lamp at ~40 %. The variant seeds the schema defaults (brightness 0–255, mireds 153–500) via `alsoSet` on `command_topic` and lets the discovered keys override them — so this map is **order-sensitive** in the same way `switchAcceptsLight` is, and says so.

Capability detection accepts `brightness: true` (z2m) **or** any `supported_color_modes` entry other than `onoff` (HA-native), which keeps the on/off-only relay lamp excluded exactly as before.

Homematic separate-mode is untouched and asserted to get **no** `publish-json-key` — a LEVEL topic takes a scalar, and an object there would break a working setup.

**Tests:** in `www/test/feezal-discovery-settable-axes.test.js` — payload rendering, both z2m axes end-to-end through the stamp, the scale fallback, `supported_color_modes`-only detection, and the separate-mode regression.

E156's slider←light axes work for **Homematic dimmers** but **not zigbee2mqtt lights** — a z2m lamp's brightness / colour-temp never appears in a slider's ⚡ picker.

**Root cause.** `lightSettableAxes` in [feezal-discovery-fragments.js](../www/packages/@feezal/feezal-element/feezal-discovery-fragments.js) gates each axis on `when: settable('brightness_command_topic')` / `settable('color_temp_command_topic')`, where `settable = key => cfg => Boolean(cfg[key])`. That key only exists on **separate-mode** lights (Homematic dimmers emit `brightness_command_topic` = the LEVEL topic). **zigbee2mqtt lights use the JSON schema**: `schema: 'json'`, a single `command_topic`, and capability flags (`brightness: true`, `supported_color_modes`/`color_temp`) — brightness is a **key inside the JSON command**, not a separate topic. So `Boolean(cfg.brightness_command_topic)` is `false` for z2m → no axis offered.

**Fix.** Make the axis `when`-guards also recognise **JSON-schema lights**: offer a brightness row when the light declares brightness capability (`schema: 'json'` + `brightness` truthy, or an explicit `brightness_command_topic`), and a colour-temp row when it declares CT (`color_temp` / `supported_color_modes` includes `color_temp`). The map **variant** must branch by schema too — a JSON light wires the slider to publish `{brightness: N}` (json payload mode, the `command_topic` + the JSON key) and read `brightness` out of the state JSON, versus the separate-mode `brightness_command_topic`/`brightness_state_topic` for Homematic. Scale still comes from `brightness_scale` (z2m 254) / mireds range as today.

**Guardrail unchanged:** still settable-only — a light with no brightness capability yields no brightness row (an on/off-only z2m light is a switch match, not a slider one), and sensors are never offered.

**Acceptance:** a discovered zigbee2mqtt lamp shows "*<lamp>* brightness" (and "*<lamp>* color temp" when supported) in a slider's ⚡ picker; picking it wires the JSON command/state correctly (publishes `{brightness: N}`, reads it back, right scale); Homematic dimmers keep working; on/off-only lights and sensors still excluded. Extend `www/test/feezal-discovery-cross-component.test.js` with a z2m JSON-schema light fixture.
