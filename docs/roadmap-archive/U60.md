# U60 — Editor: surface lost server connection (grace-period → blocking overlay)
*Archived roadmap item — Near-term Improvements. Open items: [../ROADMAP.md](../ROADMAP.md) · Index: [README.md](README.md)*

**✅ Done (07/2026).** When the editor lost its Socket.IO link to the server, nothing indicated it — the UI looked functional but no deploy/save/load/live-MQTT worked. Now a new `feezal-connection-overlay` surfaces the outage and escalates to a blocking modal.

**Wiring — consumes the existing signals.** The overlay listens on `feezal.connection` for `connected` (bubbles/composed) and `disconnected` (dispatched without bubbling — listened for directly). It is mounted once by the editor shell ([feezal-app-editor.js](../../www/src/feezal-app-editor.js)); the observed target is injectable via `.connection` for testing.

**Escalation (decided design):**
- On `disconnected` → immediately a **subtle top banner** ("Connection to server lost — reconnecting…", pulsing dot, error colour).
- After **GRACE_MS (7 s)** of continuous disconnection → promote to a **non-closable, blocking modal** (dimmed backdrop, no ✕, no click-outside-to-close). This avoids nagging on the common transient blips (server restart, sleep/wake, wifi hiccup) that Socket.IO recovers from on its own.
- On `connected` → tear the overlay down **automatically** (no manual acknowledgement) and flash a brief **"Reconnected to server"** toast.

**Modal contents:** live status line with **elapsed seconds** and **reconnect attempt count** (read from the Socket.IO manager's `reconnect_attempt` when reachable), a **Retry now** button (`socket.connect()`, guarded), and a **Reload app** escape hatch.

**Unsaved-work honesty.** The editor's site model is client-held, so a socket drop doesn't lose in-progress edits — they deploy once the link returns. The modal copy says exactly that ("Your unsaved edits stay in this browser — deploy once the connection returns") rather than a blanket "your work is safe".

**Scope:** editor only. Timers are exposed as `GRACE_MS`/`TOAST_MS` statics for testing; the component only reacts to a `disconnected` event (Socket.IO fires it only after an established connection), so the initial connect never flashes a spurious banner. Theme-aware (canonical vars) for light/dark editor.

**Ships with:** the `feezal-connection-overlay` component + editor-shell mount; a browser test (`test-browser/feezal-connection-overlay.test.js`: nothing while connected, banner on disconnect, grace→modal escalation with Retry/Reload, auto-clear + toast on reconnect, and the transient-blip case that never blocks); a TESTING.md note.

**Possible follow-up (not in v1):** distinguish "socket dropped, reconnecting" from "server actually stopped/unreachable" (repeated `connect_error`) and shift the copy accordingly; a separate viewer connection-lost indicator (same pattern, different scope).

**Relates:** `feezal-connection.js` / `feezal-connection-feezal.js` (the signals consumed), N24 / `feezal-presence` (server-side "who's connected"), the deploy flow (the concrete thing that can't happen while disconnected), a future viewer connection-lost indicator.
