# B112 — Gap snapping: vertical and horizontal indicators fight instead of showing together ✅ fixed
*Archived roadmap item — Bugs. Open items: [../ROADMAP.md](../ROADMAP.md) · Index: [README.md](README.md)*

**Reported (08/2026).** In a drag position where BOTH a vertical and a horizontal gap snap applied ([U89](U89.md)), the two indicator sets fought — only one was visible at a time, flickering by which snap won that frame.

## Cause

Not a race, and not a drawing bug: `_drawGapArrows()` had exactly **one pair of markers** (`#gap1`/`#gap2`) and picked which axis got to use them —

```js
const useX = gapX && (!gapY || gapX.distance <= gapY.distance);
```

That line was itself a fix for an earlier bug (preferring x unconditionally drew a horizontal span while the element snapped vertically), so the choice was deliberate; what was missing was a second pair to draw into. Since `distance` changes with every pointer frame, the winner flipped as the drag moved and the annotation flickered between axes.

`_snap()` already resolves the axes independently. The annotation now does too.

## Fix

The markers became **pools** — four `.gap-arrow` elements rendered from a `GAP_ARROW_COUNT` exported by [feezal-canvas-gaps.js](../../www/src/feezal-canvas-gaps.js), so the count follows from the candidate shape (two spans per axis × two axes) instead of being a number repeated in the template.

`_drawGapArrows` became `_drawGapGuides`: it collects what each axis wants first and applies second, because the pools are shared and nothing can be written until both axes have been asked. Surplus markers are hidden, so a one-axis proposal looks exactly as it did before.

Three places had to hide every overlay — drag end, palette drop, and a modifier key changing mid-gesture — and each carried its own hard-coded id list. Those lists would have silently stopped covering the second axis (and B113's helper lines) the moment the pools appeared, so they were replaced by one `hideSnapOverlays()` helper over a single selector in [feezal-canvas-geometry.js](../../www/src/feezal-canvas-geometry.js).

**Verified** in the real editor ([editor-snap-guides.test.js](../../www/test-e2e/editor-snap-guides.test.js)) with a layout carrying two independent 50px rhythms that meet at one point — a drag there now annotates both axes at once (2 horizontal + 2 vertical spans, all labelled 50) and a drag in range of only one axis still annotates only that one. Reverting the one-axis selection makes both the both-axes case and the helper-line case fail.
