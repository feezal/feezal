# U108 — layout-app: optional search filter for the menu drawer ✅ done
*Archived roadmap item — Editor UX. Open items: [../ROADMAP.md](../ROADMAP.md) · Index: [README.md](README.md)*

**Requested (08/2026).** An opt-in search input at the top of the
navigation drawer that live-filters the DRAWER ENTRIES (not the view's
elements — that is E170) by label, debounced like E170.

- **Opt-in knob** (e.g. `drawer-search`, boolean, default off) + inspector
  switch in the Drawer section.
- Filters across BOTH navigation levels (U103): matching pages stay, a
  section stays while any of its children match (auto-expanded in groups
  mode so the hits are visible); clearing restores the previous
  open/collapse state. Works in every nav-style's level-1 surface —
  full drawer, accordion overlay, rail-panel's entry panel, tabs' section
  drawer (the slim icon rail itself gets no input — the overlay/panel
  carries it).
- Styling follows the drawer chrome (entry inset, drawer colors, N43-safe
  in the editor preview); small × clear button in the field; Esc clears
  first, then closes an overlay drawer (the existing Escape behavior).
- Keyboard: the input participates in the drawer's D-pad flow — ArrowDown
  from the field focuses the first visible entry; typing never steals
  Enter/Space from a focused entry.
- The narrow overlay keeps the field visible (sticky at the drawer top)
  while the entry list scrolls.

**Relates:** E170 (view-element search — shared debounce/matching
helpers where sensible, but this filters nav entries), U103 (two-level
drawer), U94 (drawer scrollbar — the field must not overlap the thin
scrollbar).

## Implemented (08/2026)

- **Knob**: `drawer-search` (boolean, default off) + an sl-switch in the
  custom inspector's Drawer section (B88 discipline).
- **Field**: in the drawer SHELL above the `.drawer-nav` scroller — the slot
  the B129 restructure left — so it stays put while entries scroll (also the
  narrow overlay, for free). Search icon, × clear button, drawer chrome via
  canonical vars. The slim/edge rail hides it at rest (same selector family
  as the label collapse); rail-panel's entry panel carries its own field.
- **Filtering**: exported pure `filterNav(tree, query)` → `{tree, open}` —
  case-insensitive label match, debounced 150 ms; matching pages stay, a
  section stays while any page matches (narrowed to the hits), a match on
  the SECTION label keeps all its pages; `open` names hit sections. The
  render UNIONS that into the shown open-set without mutating the user's
  `_openSections`, and the first non-empty filter snapshots the set so
  clearing restores the previous open/collapsed state exactly. The icon
  rail in rail-panel mode is never filtered (level-1 stays complete).
- **Keyboard**: field keys never reach the drawer's D-pad handler
  (Left/Right stay the text cursor); ArrowDown focuses the first visible
  entry; Esc clears first — an Esc on an empty field bubbles on to the
  existing overlay-close.

7 browser cases in the layout-app suite (80 green): the pure filter rules,
opt-in + shell placement (structurally: the field is NOT inside the
scroller), narrowing + hit-expansion + restore-on-clear (the user set is
never mutated by filtering — pinned), the debounce, ArrowDown hand-off,
the two-stage Esc, and the rail-panel field incl. the never-filtered rail.
Neutering filterNav flips the suite red (probed).
