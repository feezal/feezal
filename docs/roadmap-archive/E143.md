# E143 — Lock element family parity: `glass-lock` + `metro-lock` (extract `feezal-controller-lock`)
*Archived roadmap item — Element Ecosystem. Open items: [../ROADMAP.md](../ROADMAP.md) · Index: [README.md](README.md)*

**✅ Done (07/2026).** `circle-lock` was the only lock element (an E114 parity gap). Extracted the lock contract into a controller and added the glass + metro cards.

**Shipped:**
- **`@feezal/feezal-controller-lock`** — the smart-door-lock contract as a Lit reactive controller (`LockController` + `lockAttributes` + `lockDiscoveryMap` + `LOCK_CONSUMED_ATTRIBUTES`). Owns state parsing (locked / unlocked / jammed), lock/unlock/open command publishing, availability (via the base), and — added during implementation:
  - **E124 low-battery** (smart locks are battery devices): `batteryLowAttributes` spread in, `batteryLow` state, auto-stamped `subscribe-battery-low`, rendered as the shared battery badge.
  - **E135 error signal**: an optional `subscribe-error` topic surfaces the device's specific fault text (Keymatic clutch/motor faults, HmIP-DLD jammed/load/end-stop) as an error badge; the `jammed` state and any error both drive the `faulted` visual.
  - **Homematic OPEN action**: `publish-open` / `payload-open` — the door-release action distinct from unlock (Keymatic / HmIP-DLD). Offered only when configured (zigbee locks omit it). HA `payload_open` maps on the command topic; a separate `publish-open` topic covers the Homematic OPEN datapoint.
- **`circle-lock`** refactored to a view over the controller (behaviour preserved) + the new battery/error/open surfaces.
- **`glass-lock`** (new) — frosted card, state icon/colour, Lock/Unlock/Open buttons, battery + error + unavailable badges.
- **`metro-lock`** (new) — Metro tile; state colour on the face (accent locked / amber unlocked / error jammed), actions on the flip-back so an accidental tap can't unlock; battery in the face, availability via the `!` badge.
- Registered all three in `www/package.json`, the `feezal-controller-parity.test.js` (E137/E114 contract), and the generated element manifest; `circle-lock` → 3.1.0. Full www suite (884) + parity (36) green; build clean.

**Deferred (open):** `eink-lock` (same controller, follow the family later); lock autodiscovery for Homematic/z2m is **E144**.

**Relates:** E114 (the parity gap closed), E137 (controller-first rule), E139 (fancy-lock — reuses this controller), E135 (lock error signal), E124 (battery), E144 (lock autodiscovery — populates these cards), circle-lock (reference).
