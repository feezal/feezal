# E140 — Per-state icon colour: configurable CSS vars for every state-driven icon
*Archived roadmap item — Element ecosystem. Open items: [../ROADMAP.md](../ROADMAP.md) · Index: [README.md](README.md)*

**✅ Done (07/2026).** Every element whose icon changes with state can now colour **each** state via a Style-inspector CSS var. The gap was the **inactive** side of the Glass family; the other families were already consistent (audited below).

**Audit (what already existed vs the gap):**
- **Circle** — complete already, and the naming template: every state has its own var (`--feezal-light-on-color`/`-off-color`, `--feezal-contact-open-color`/`-tilt-color`, `--feezal-motion-active-color`, `--feezal-lock-locked/unlocked/jammed-color`, `--feezal-climate-heat/cool/idle-color`, `--feezal-fan-on/off-color`, …), each defaulting to the controller's canonical `activeColorVar()` (sensor motion → `--accent-color`, alarm → `--error-color`, contact → `--primary-color`).
- **Glass** — the **gap**: the ON/active side was exposed (`--feezal-glass-accent` / `--feezal-glass-active-color` / open/tilt), but the **inactive** side (off / inactive / closed / clear) fell through to the *unexposed shared* `--feezal-glass-muted`, so it wasn't per-element settable. `glass-lock` was the only complete one.
- **Metro** — icons are always the uniform tile-text (`--feezal-metro-text`); state is signalled by the **tile background**, handled in **[E141](E141.md)**. No per-state icon colour concept — intentionally left as-is.
- **Eink** — monochrome (the active state inverts the whole card); no icon colour to expose — N/A by design.
- **Material / Carbon / Paper** — the only state-driven member is the switch, a toggle *control* (track/thumb); `material-switch` already exposes full per-state control colours (`--feezal-switch-track-on/off`, `-thumb-on/off`, …). No state icon — already satisfied.

**Fix (Glass — the concrete work).** Each glass state-icon element gained a dedicated **inactive-state** icon-colour var, threaded into the icon's colour as `var(--feezal-glass-<state>-color, var(--feezal-glass-muted, rgba(29,29,31,0.55)))` so it **defaults to the frost muted** (untouched cards identical) but is now overridable:
- `glass-switch` / `glass-light` → `--feezal-glass-off-color`
- `glass-button` → `--feezal-glass-inactive-color`
- `glass-contact` → `--feezal-glass-closed-color`
- `glass-sensor` / `glass-motion` → `--feezal-glass-clear-color`

Naming follows each family's own scheme (glass-lock's `--feezal-glass-<state>-color` was the in-family template); the active-side defaults stay theme-driven, so this is purely additive.

**Ships with:** the six glass inactive-icon-colour vars, patch bumps on each touched package, a browser test (`test-browser/feezal-glass-icon-colors.test.js`: each glass element exposes both its inactive and active icon-colour var, and the inactive one defaults to the frost muted), and a TESTING.md note.

**Relates:** **E114** (parity — same knobs across families; this closes glass's gap against circle), **E137** (controllers own the default per-state colour semantics), §5.1 theme-variable discipline (defaults), `basic-icon-value` (the per-state-colour precedent), E138 (colour semantics per function), **[E141](E141.md)** (the tile-background sibling for the metro family — built alongside this).
