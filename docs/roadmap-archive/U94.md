# U94 — layout-app: themed thin drawer scrollbar (thumb currently invisible) ✅ done
*Archived roadmap item — Editor UX. Open items: [../ROADMAP.md](../ROADMAP.md) · Index: [README.md](README.md)*

**Reported (08/2026).** With an overflowing drawer navigation, scrolling worked but the **thumb was invisible** (midnight-blue theme — the platform default thumb disappears against a themed drawer background), and on Chrome/Windows the bar was the full-width native one, far too heavy beside a navigation drawer.

**Cause:** shadow-DOM content gets the platform scrollbar, and the element had no scrollbar styling at all — so nothing tied the thumb to the theme.

**Fix:** thin, rounded, themed scrollbars on **both** of the app shell's scroll surfaces — the drawer and the content area, so the two match:

- `scrollbar-width: thin` + `scrollbar-color: <thumb> transparent` (Firefox and the standards path);
- `::-webkit-scrollbar { width: 8px }`, a transparent track, and `::-webkit-scrollbar-thumb { border-radius: 4px }` for the rounded ends (Chromium/Safari). The `::-webkit-scrollbar-corner` is made transparent too — Chromium otherwise paints the corner where two bars meet with its own default, a pale square against a dark drawer.

The thumb colour is a new style knob, `--feezal-app-scrollbar-color`, defaulting to the canonical `--secondary-text-color` so it tracks the theme rather than being a fixed grey that happens to work on one background. Exposed as a `color` style descriptor, so it is adjustable from the inspector.

**A note on the selector:** the drawer's scroll container is `.drawer`, not a separate `.nav` — the first attempt styled a class that does not exist in the template and silently did nothing. The tests caught it immediately.

**Verified** in `test-browser/layout-app-drawer-geometry.test.js`: both surfaces request a thin scrollbar, the thumb resolves from the theme over a transparent track, the knob overrides the default, and the descriptor is declared. Deliberately asserted on **computed style rather than pixels** — headless Linux draws overlay scrollbars (zero gutter, thumb only while scrolling), so a screenshot check would prove nothing about the Chrome/Windows bar this was reported against. Confirmed to fail when the rule is removed.

**Not verifiable from here:** the actual rendered appearance on Chrome/Windows, which is the reporting platform. The standards properties are confirmed applied and the `::-webkit-` rules are the standard spelling, but the visual is worth a look on the reporting machine.

**Relates:** B90 (drawer geometry — same element), the editor's own thin-scrollbar machinery (editor chrome only; it does not reach viewer shadow roots).
