# A30 — Split `native-discovery.js` into per-source recognizer modules
*Archived roadmap item — Architecture & Infrastructure. Open items: [../ROADMAP.md](../ROADMAP.md) · Index: [README.md](README.md)*

**✅ Done (07/2026).** `native-discovery.js` had grown to ~1710 lines / 9 recognizers (7 Homematic + WLED + evcc). Split **by source/vendor** into `server/src/mqtt/recognizers/`, with `native-discovery.js` kept as the thin orchestrator + framework (now ~185 lines).

**Layout:**
- **`recognizers/homematic.js`** — all 7 HM recognizers (climate / contact / cover / light / switch / sensor / lock) **plus their shared `hm` infrastructure**: `hmSet`/`hmStatus`/`hmParamset`/`buildHmModes`, the HmIP virtual-receiver run grouping (`hmipVirtualGroup`), the channel-type allowlists, the hm-prefix + climate-staleness config, and the B65 `:0` maintenance correlation (`indexMaintenance`/`resolveMaintSeg`/`applyHmAvailability`) + the B64 stale-run-leader filter (`isStaleHmGroup`). Self-contained: owns its own ordered `hmRecognizers` array (so `isStaleHmGroup` can search it) and needs nothing back from the framework.
- **`recognizers/wled.js`, `recognizers/evcc.js`** — the two standalone recognizers.
- Future sources land as one new file + one registry line.

**`native-discovery.js` stays the orchestrator + framework:** the `match`/`accumulate`/`promote` dispatch loop, the entity registry (`nativeEntities`/`nativeEntityTs`), `extractValue`/`parsePayload`, and the `recognizers` registry array. It imports the per-source modules and calls homematic's read-time helpers (`hm.indexMaintenance`, `hm.isStaleHmGroup`, `hm.applyHmAvailability`, `hm.getClimateStaleMs`, `hm.clearHmMaintenance`). **`module.exports` API is unchanged** — callers and tests keep importing `native-discovery.js` (the HM config setters are re-exported from `hm`).

**Design decisions that made it clean:**
- **One-directional import** (framework → recognizers). The HM `:0` glue and stale-filter moved *with* the HM code (they depend on the live `hmPrefix`, which a CommonJS snapshot in the framework could not track), so there is no circular import — `homematic.js` requires nothing from `native-discovery.js`.
- **Registry order preserved exactly** (`climate, wled, contact, cover, light, switch, sensor, lock, evcc`) via `[hm.hmRecognizers[0], wledRecognizer, ...hm.hmRecognizers.slice(1), evccRecognizer]` — recognizer precedence is behavioural.
- **Pure move, no behaviour change** — the code blocks were extracted verbatim; the only edit inside them was pointing `isStaleHmGroup` at homematic's own `hmRecognizers` array.

**Acceptance met:** `server/test/native-discovery.test.js` stayed **green unchanged**, and the **full server suite (458 tests) passes** — the module is imported by `app.js`/routes, so the whole suite is the real safety net.

**Not done (explicit follow-up):** splitting the test file per-source is a later, optional task.
