# E169 — `scrypted-camera`: embed Scrypted NVR live/events views ✅ done
*Archived roadmap item — Element Ecosystem. Open items: [../ROADMAP.md](../ROADMAP.md) · Index: [README.md](README.md)*

**Idea (08/2026), researched against how Home Assistant does it.** Scrypted
(koush's camera hub — HomeKit/Arlo/Unifi/… bridges, hardware-accelerated
streams, object detection) is the other big camera platform besides Frigate,
and its HA integration architecture is the OPPOSITE of Frigate's — in
feezal's favour.

**How HA integrates Scrypted (researched 08/2026, sources below):**

1. **HA does not create camera entities — but it DOES proxy the card URL**
   *(corrected 08/2026 — the first write-up claimed the browser talks to
   Scrypted directly; `ha_scrypted`'s `http.py` disproves that: it registers
   `/api/scrypted/{token}/{path:.*}` as an HA view and forwards to Scrypted
   with a Bearer token, so the tokenized card URL is minted AND served by
   Home Assistant)*. No camera entities:
   [koush/ha_scrypted#8](https://github.com/koush/ha_scrypted/issues/8)
   requesting them has sat open, unanswered, since 2023. The card URLs:
   - new cards: web components from
     `/api/scrypted/<token>/endpoint/@scrypted/nvr/assets/web-components.js`;
   - legacy cards: a plain HA *Webpage (iframe) card* pointed at
     `/api/scrypted/<token>/endpoint/@scrypted/nvr/public/#/iframe/<id>`,
     with `#/iframegrid?ids=<id1>,<id2>` (grid) and
     `#/iframeevents?ids=…` (event reel) variants, and query knobs
     `live=true`, `destination=low-resolution|remote|local`,
     `speaker/microphone=on|off`, `imageClick/videoClick=ha|app|none`.
   **Without Home Assistant** the same iframe views are served by the
   Scrypted server itself at
   `https://<scrypted-host>:10443/endpoint/@scrypted/nvr/public/#/iframe/<id>`
   — behind Scrypted's own login (sign in once inside the frame; third-party
   cookie partitioning scopes that login to the embedding dashboard's
   origin). Either way it is iframe embedding, not fetch — no CORS fight, no
   feezal-server transport, pure-MQTT-principle-compatible by the existing
   precedent (element-level HTTP, like the U74 MJPEG feed).
2. **The NVR cards are part of the PAID Scrypted NVR plugin.** The iframe
   endpoints above are `@scrypted/nvr` endpoints; without the subscription
   there is no embeddable live view from Scrypted itself.
3. **MQTT: Scrypted's MQTT plugin publishes standard HA discovery**
   (verified in the plugin's `autodiscovery.ts`): configs at
   `homeassistant/<component>/scrypted-<id>/<iface>/config`, components
   switch / light / lock / binary_sensor (motion, door, window, occupancy,
   flood, audio) / sensor, state at `scrypted/<id>/<property>`, commands at
   `…/set`. **No camera/image publishing at all.** Consequence: feezal's
   existing HA-discovery consumer (`server/src/mqtt/discovery.js`) should
   already pick up Scrypted's non-camera devices AND camera motion sensors
   with zero new code — verify, then no scrypted recognizer is needed for
   sensors.
4. **Free path without NVR:** the `@scrypted/webhook` plugin mints
   tokenized HTTP URLs for camera snapshots (`…/takePicture`), device state
   and control; the rebroadcast plugin exposes an RTSP restream
   (`rtsp://<ip>:<port>/<stream-id>`) that go2rtc can gateway to
   WebRTC/HLS/MJPEG — which lands exactly on `basic-camera`'s existing
   `mjpeg`/`hls`/`webrtc`/`image` types. The free tier needs no new
   element; the new element's value is the NVR views.

**Element sketch (refine before building):** `feezal-element-basic-scrypted`
wrapping the iframe endpoints. Attributes: `base-url`, `token`, `camera-id`
(or `ids` for grid), `view` (`live | grid | events`), `destination`,
`speaker`, `microphone`; `pause-when-hidden` with basic-camera's semantics
(drop the iframe `src` off-screen). Motion/state chips come free via the
MQTT discovery path (3). Reuse basic-camera's popup pattern for a
full-screen NVR view.

**Open questions:**
- Paid-NVR gating: is an element that requires a subscription acceptable as
  an official `basic-*`? Alternative: document webhook-snapshot + go2rtc as
  the free recipe *on basic-camera* and scope this element to NVR owners.
- Token lifetime: Scrypted granular tokens are limited to 90 days (with
  2FA) — the element should surface an expired-token state rather than a
  silently black iframe.
- Iframe vs web components: the legacy iframe endpoints are documented as
  deprecated-ish ("use the new cards"); the new web-components path means
  loading Scrypted's JS into the viewer — check CSP/static-export
  implications before choosing.
- Mixed content: an https feezal viewer cannot embed an http Scrypted —
  same constraint as U74, document it.

**Relates:** E168 (the Frigate counterpart — proxy-shaped, unlike this),
E163 ✅ / U74 (basic-camera and its feed types — the free-tier answer),
E149 (HA discovery consumer this leans on), the pure-MQTT principle
(satisfied here without a carve-out).

## Implemented (08/2026)

Shipped in two parts, with the open questions decided pragmatically:

1. **`@feezal/feezal-element-basic-scrypted` (3.0.1)** — a NEW element (the
   maintainer's call: not an iframe type on basic-camera). Paste the NVR card
   webpage URL into `src`; `view` rewrites one pasted URL between `live` /
   `grid` / `events` (the event reel shows history — events from before the
   page opened); `camera-ids`, `live`, `destination`, `speaker`, `microphone`
   are owned params (anything else pasted survives; ids keep literal commas);
   a URL without a recognizable `#/iframe` fragment is embedded unchanged.
   `pause-when-hidden` mirrors basic-camera's teardown. The rewrite rules are
   an exported pure `composeScryptedUrl()`, 22 browser tests, revert-probed.
2. **Discovery comfort** — a `scrypted` recognizer over Scrypted's OWN
   `homeassistant/*` configs (nodeId `scrypted-<mqttId>-<device.id>`,
   MotionSensor = the camera telltale; device id = last dash-segment)
   synthesizes `scrypted-camera` entities; `resolveElementTag` falls back
   cross-family to basic-scrypted (the Frigate→basic-camera pattern); the
   Generate wizard shows a **Scrypted NVR card URL** row (paste ONE camera's
   URL — the token is instance-wide) and `applyScryptedNvrSrc()` swaps each
   camera's device id into the fragment; the ⚡ picker reuses the remembered
   URL. Without a URL a pick still wires `camera-ids` (element shows its
   paste hint) — nothing guessable, the token can't travel over MQTT.

Open questions, as decided: paid-NVR gating — ships as an official
`basic-*` anyway, the description says "requires the Scrypted NVR plugin"
and points the free tier at basic-camera + go2rtc; token expiry — documented
in the `src` help ("a feed that turns black usually means: copy a fresh
URL"), not detected (the iframe is cross-origin, opaque by design); legacy
iframe vs web components — the iframe endpoint, deliberately (self-contained,
no third-party JS in the viewer, and it is what HA's own Webpage cards use);
mixed content — documented, not worked around.

Not done (open ideas, file separately if wanted): an upstream PR adding an
HA `camera` component (snapshot-on-motion over MQTT) to Scrypted's MQTT
plugin — would make Scrypted cameras appear via the PLAIN HA discovery path
with zero feezal code, the principle-pure baseline for non-NVR users.
