# B73 — Background editor (view styles): solid + gradient colour fields should use the style-inspector var-autocomplete, not a dropdown; widen the too-small percent input
*Archived roadmap item — Bugs. Open items: [../ROADMAP.md](../ROADMAP.md) · Index: [README.md](README.md)*

**✅ Fixed (07/2026).** The view-styles background editor's colour fields used a separate `.var-menu` `<select>` for theme variables (on both the solid input and every gradient stop), unlike the rest of the Style inspector, and the gradient stop percent input was too narrow to read.

**Fix.** Replaced the `.var-menu` dropdown with an **autocompleting `var(--…)` input** on the solid colour field and every gradient stop — typing `var(` offers the canonical theme vars inline (arrow/enter/escape navigation, fixed-position dropdown), the same UX as the Style inspector's CSS-variable autocomplete. The colour input already kept a literal or `var(--…)` verbatim (U59), so only the suggestion UI changed. Widened the stop percent input (`.pct`) from 52px → 68px so a two/three-digit value is fully visible.

**Ships with:** the new `_varAcInput`/`_varAcKeydown`/`_varAcPick` autocomplete in `feezal-style-editor-background.js` (removed `_varMenu`), unit tests in `test/feezal-style-editor-background.test.js` (opens on `var(--pri`, completes solid + gradient-stop values, closes when the text no longer ends with an open `var(`).

**Note:** implemented as a focused autocomplete in the gradient editor (scoped to the canonical `THEME_VARS`); a future refactor could extract the Style inspector's autocomplete into a shared control so the two share one implementation.

**Relates:** U59 (the gradient editor + the literal-or-`var(--…)` stop model), the Style inspector `var(--…)` autocomplete (`feezal-sidebar-inspector-styles.js` — the UX mirrored), the canonical theme-variable set (`THEME_VARS`).
