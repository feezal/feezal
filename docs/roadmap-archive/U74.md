# U74 — Generate wizard: set a family-matched theme so the app looks like the family screenshot ✅ done
*Archived roadmap item — Editor UX. Open items: [../ROADMAP.md](../ROADMAP.md) · Index: [README.md](README.md)*

**Follow-up fix (07/2026).** The glass sub-view gradient is now the feezal **default gradient** `linear-gradient(180deg, #0284c7 0%, #1e293b 100%)`, written as **`background-image`** (the exact property the Background style editor reads/writes) instead of the `background` shorthand — the shorthand rendered a different/stale colour and the inspector didn't reflect it until the user re-edited. The Background editor's gradient parser was also hardened to accept a linear-gradient with **no explicit angle** (the browser drops the default `180deg` when a gradient round-trips through an inline style), so the inspector shows the two stops correctly on first open.

**Done (07/2026).** When `_generateApp` creates a fresh app shell it sets the site theme to match the chosen family — glass → `feezal-theme-midnight-blue`, metro → `feezal-theme-metro`, circle → `feezal-theme-gruvbox-light` (`FAMILY_THEME` map; applied as the theme class on `<feezal-site>`, stripping any prior theme class). For glass, each newly created sub-view also gets the feezal signature gradient as its `background` (`GLASS_GRADIENT` — the glass wallpaper's colour stops as pure CSS). The theme is only set on a fresh shell (a re-run never clobbers a theme the user has since picked), and the sub-view gradient is a one-time stamp on newly created views. Other families keep the default.

**Requested (07/2026).** The App generator should apply a **site theme that matches the chosen element family**, so a generated app looks like its U71 screenshot rather than the fresh-install default:

| family | site theme | extra |
|---|---|---|
| **Glass** | `feezal-theme-midnight-blue` (the reporter's "midnight-dark" — the dark base the frost shines against) | set **each generated sub-view's background to the default gradient** wallpaper (what makes the frosted cards read) |
| **Metro** | `feezal-theme-metro` | — |
| **Circle** | `feezal-theme-gruvbox-light` | — |

The other families (eink / basic / material) keep the default for now — add their theme when a screenshot exists (pairs with **U71**).

**Grounding.** `_generateApp` in `feezal-generate-dialog.js` builds the shell + sub-views; on confirm it would also **(a)** set the site theme — a theme is a **class on `<feezal-site>`** (`pkgToClass` in `feezal-theme-select.js`), persisted as `config.theme`; reuse the theme sidebar's apply path so it saves + repaints — and **(b)** for glass, set each created sub-view's `background` / `background-image` to the **default gradient** (the `feezal-theme-glass` wallpaper gradient — pin the exact value at build; a per-view background already lives as the style-inspector `background`, so write the same inline form). Only the sub-views the run creates are touched; a re-run must not clobber a background the user has since changed.

**Decisions to make:** whether setting the theme **overrides an existing site theme** on every generate (the request implies yes — "set site theme to X" to match the screenshots) or only when the app shell is freshly created; and whether the glass sub-view gradient is a one-time stamp (editable afterwards) — recommend yes, like every other generated default. Fold into the one-undo-snapshot scaffold. *(Resolved: theme is set only when the shell is freshly created; the gradient is a one-time stamp on newly created views.)*

**Ships with:** the per-family theme map + the glass sub-view gradient in `_generateApp`, reuse of the theme apply/persist path, a browser test (glass → the `feezal-theme-midnight-blue` class on the site + sub-views carry the gradient; metro → `feezal-theme-metro`; circle → `feezal-theme-gruvbox-light`), and a `docs/TESTING.md` line in the Generate-wizard §.
