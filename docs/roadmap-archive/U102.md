# U102 — Vertical guide-line label: flip 180°, right of the line, near the top ✅ done
*Archived roadmap item — Editor UX. Open items: [../ROADMAP.md](../ROADMAP.md) · Index: [README.md](README.md)*

**Requested (08/2026).** [U99](U99.md) shipped the vertical readout rotated a quarter turn left — reading bottom-up, left of the line, near the canvas bottom. Wanted: 180° from that (reading top-down), to the **right** of the line, near the **top**. Horizontal labels unchanged.

## `writing-mode`, not a second rotate()

The obvious change is `rotate(-90deg)` → `rotate(90deg)`, but the origin then has to be nudged by the label's own line-height to clear the line: rotating clockwise about the top-left corner swings the glyph band to the *left* of the origin, i.e. over the line it is annotating. That correction is a magic number tied to a font size — exactly the sort of arithmetic that drifts the first time someone changes the type scale.

`writing-mode: vertical-rl` gives top-down text with no transform at all, and puts the glyph band beside the line by construction. The placement is then just `left: 4px; top: 6px` — right of the line, anchored at the top.

Everything else about the readout is unchanged: it is still a `::after` fed by `data-pos`, still inherits the line's colour ([U101](U101.md) ✅), still carries the bare value ([B117](B117.md) ✅), and still never intercepts the pointer.

**Verified** in a real editor ([editor-snap-guides.test.js](../../www/test-e2e/editor-snap-guides.test.js)) by reading the computed `::after` style: `vertical-rl` with **no** transform, offset past the line's own width (so it is on the right), and anchored within a few px of the top. The horizontal readout is asserted to stay upright and `horizontal-tb` in the same pass. Reverting to the U99 rotation fails it.
