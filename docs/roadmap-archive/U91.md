# U91 — Distribute: never overlap (edge-to-edge fallback when the span is too tight) ✅ done
*Archived roadmap item — Editor UX. Open items: [../ROADMAP.md](../ROADMAP.md) · Index: [README.md](README.md)*

**Requested (08/2026), refined.** NOT a separate Pack operation — U83's distribute behaviour stays exactly as it is (equal gaps between the outermost elements, outer anchors fixed) and is liked. The refinement is a single rule on top: **never overlap — gaps are allowed.**

**What it was doing.** The gap is `(span − Σsizes) / (n − 1)`, and nothing clamped it. Once the selection summed to more than the span between its outermost two, that went **negative** — which still spaced the elements "evenly", by stacking them on top of each other. Predictable, and never what anyone wants.

**The rule**, exactly as the item specifies: `gap = max(0, (span − Σsizes) / (n − 1))`.

The interesting part is what that implies for the anchors, and it is the one trade this makes:

- **Roomy (unchanged):** BOTH outermost elements are pinned, so the selection keeps its bounds and rounding cannot drift them.
- **Tight (new):** the strip must grow past the old outer edge, so only the FIRST element is pinned and everything else lands flush against its predecessor. The last element moves — which it never does in the roomy case. That is the acceptable half of "the strip extends past the old outermost position; that is acceptable, overlap is not".

Both cases fall out of one `pinned` expression rather than two code paths, so they cannot drift apart.

Cross-axis positions untouched, U83's ordering rule unchanged, one undo entry, locked elements respected — all inherited, none of it needed changing.

**Verified** in `test/feezal-canvas-align.test.js` (7 new): packs edge-to-edge when tight, never produces a negative gap under heavy crowding (asserted pairwise over the placed result, not just on the gap value), the strip growing past the old outer edge, the first element staying put, the roomy case still pinning both anchors, vertical packing, and that an exactly-touching layout is already correct so nothing moves. Confirmed to fail when the clamp is reverted.

**Relates:** U83 ✅ (align & distribute — this is one rule on top), U89 ✅ (the live equal-gap hint, same geometry module family).
