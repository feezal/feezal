# U59 — Style inspector gradient editor: allow themed CSS vars as gradient stops
*Archived roadmap item — Near-term Improvements. Open items: [../ROADMAP.md](../ROADMAP.md) · Index: [README.md](README.md)*

**✅ Done (07/2026).** Gradient stops can now reference the canonical themed CSS custom properties, exactly as the Solid background colour already could — so a gradient **re-tints when the theme changes** instead of freezing to a literal hex.

**Before.** The Solid path accepted `var(--…)` (resolving swatch, empty = theme default), but every gradient stop was a bare `input[type=color]` and each colour was normalised to hex (`_hexish`), so a gradient could never follow the active theme.

**Changes** (all in [www/src/feezal-style-editor-background.js](../../www/src/feezal-style-editor-background.js)):
- **Stops carry the authored string.** `{color, pos}` now keeps the authored `color` — a `var(--…)` reference or a literal hex/named/rgb — rather than hex-normalising it. Only the **swatch preview** resolves it (via the existing `_resolveHex` throwaway-element probe); an unresolvable value shows the checkerboard, same affordance as Solid.
- **Serialisation emits it verbatim.** `_gradientValue()` was already `` `${s.color} ${s.pos}%` ``, so a `var(--…)` stop serialises straight into `linear-/radial-gradient(...)` and the browser resolves it against the live theme cascade.
- **Parser round-trips var().** `_parseStops` previously bailed on any non-hex stop; it now accepts a `var(…)` (or anything `_hexish` resolves) and keeps the authored text, so re-opening the inspector on a themed gradient no longer drops back to defaults.
- **Editable as literal OR var.** Each stop row mirrors the Solid control: a free-text value input (accepts `var(--…)`) + a resolving swatch, plus a compact **theme-var quick-pick menu** (`_varMenu`) offering the canonical set so authors don't memorise names. The same var menu was added to the Solid input.

**Canonical set offered** (per CLAUDE.md / element-spec §5.1): `--primary-background-color`, `--secondary-background-color`, `--primary-text-color`, `--secondary-text-color`, `--disabled-text-color`, `--divider-color`, `--primary-color`, `--accent-color`, `--error-color`.

**Ships with:** the stop-shape/parse/serialise change + the per-stop value-input/swatch/var-menu (and the Solid var menu); unit tests round-tripping `var()` stops (linear with one var + one hex; radial with two vars) alongside the unchanged hex tests; a TESTING.md note on the N34 background editor.

**Relates:** the Solid var support this mirrors (same file), §5.1 theme-variable discipline (the canonical set), U18/themes (why a themed gradient matters — it re-tints on theme switch), U61 (editor/viewer background preview fidelity — adjacent background authoring).
