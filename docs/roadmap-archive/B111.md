# B111 — App generation: Frigate camera elements come out with empty `src` despite a configured Frigate URL ✅ fixed
*Archived roadmap item — Bugs. Open items: [../ROADMAP.md](../ROADMAP.md) · Index: [README.md](README.md)*

**Reported (08/2026).** Generating an app produced a camera element with `events-camera=terrasse` — so the Frigate wiring itself ran — but an empty `src`, despite a Frigate URL being entered at the start of the wizard.

## It was none of the three suspects

The item listed three, in likelihood order. All three were wrong, and ruling them out is what found the real one:

1. ~~`_frigateUrl` empty because the input commits on blur~~ — the row binds `@sl-input`, so it commits on every keystroke.
2. ~~`entity.source !== 'frigate'` on the App path~~ — the recognizer sets `source` on **both** entity paths (topic-derived and `frigate/stats` roster), `_reviewBuckets` and `_mvPlan` pass the original object through, and an App-path test with a recognizer-shaped entity stamps `src` correctly. It still does — that test is now a permanent regression guard.
3. ~~A camera path bypassing `_stampEntity`~~ — there are exactly two stamp call sites and both go through it.

## The actual cause: a guard evaluated before an await

```js
if (!this._frigateUrl && this._hasFrigate()) {
    this._frigateUrl = localStorage.getItem('feezal.frigateUrl') || await guessFrigateUrl();
}
```

The guard runs **before** `await guessFrigateUrl()`, which is an HTTP round-trip, at the end of the discovery **polling loop** — i.e. seconds after the dialog opened, with the URL field already on screen. Typing during that window is overwritten when the guess lands. And `guessFrigateUrl()` returns `''` whenever there is no bridge to derive a host from, so the typed URL was replaced with an empty string.

Everything downstream was innocent: the entity was correct, the wiring ran (hence `events-camera`), and `applyFrigateLiveFeed` simply saw an empty base URL and declined.

**Fix:** re-check after the await, and only ever FILL an empty field —
`if (!this._frigateUrl && guess) this._frigateUrl = guess;`

## Why it needed two tests

The App-path stamp test passes against the *unfixed* code, because the entity was never the problem. Only a test shaped like the race catches it: hold `/api/bridge/status` open, wait until the guess is genuinely in flight, type, then release. Verified by re-introducing the unconditional assignment — that test fails, the stamp test does not.

**Relates:** E163 (the Frigate recognizer), the App-generation wizard, `applyFrigateLiveFeed`.
