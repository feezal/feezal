# U75 — Generate review: checkbox is checkbox-only; multi-row select + bulk "move to room" ✅ done
*Archived roadmap item — Editor UX. Open items: [../ROADMAP.md](../ROADMAP.md) · Index: [README.md](README.md)*

**Follow-up fix (07/2026).** The first cut made the include `<sl-checkbox>` unclickable (its own `sl-change` never toggled reliably next to the row's `pointerdown`/`preventDefault`). Fixed by the proven bucket-header pattern: the `<sl-checkbox>` is display-only (`pointer-events:none`) inside a wrapper span that owns the click (`_toggleChecked`) and stops it reaching the row's selection gesture.

**Done (07/2026).** The review row's two concerns are split. The include **checkbox** is now atomic — an `@sl-change` toggle on the `<sl-checkbox>` (with `@pointerdown` stopPropagation) flips only that device's `_checked`; clicking the row **body** no longer touches it. The row body drives a **new `_selected` set** via a second `RangeSelect` (`_selReview`) — `_selPress` routes to it in the review stage — so click / Shift-range / drag now *select* rows (highlight) instead of toggling checkboxes. A **bulk bar** appears while ≥1 row is selected: "N selected", **Move to room…** (existing rooms + the U70 create-new sentinel, `_bulkMove`), **Check** / **Uncheck** (`_bulkCheck`), **Clear** (`_clearSelection`). A bulk move (or bulk create-new) reassigns every selected key and clears the selection; the selection is ephemeral and resets on re-entering review. Decisions taken from the open questions: bulk-move does **not** auto-check (kept orthogonal — the bar has explicit Check/Uncheck), and the selection **clears** after a bulk move.

**Requested (07/2026).** Two coupled complaints about the review list's row interaction:
1. **The whole row toggles the include checkbox.** Clicking anywhere on a device row flips its checkbox (the U68/U69 range/drag select is wired to `_checked`), which is far too easy to trigger by accident. The **checkbox should only toggle when you click the checkbox itself**.
2. **No bulk room change.** Moving many devices to the same room means opening each row's dropdown one at a time. You should be able to **select multiple rows and set the room for all of them at once**.

This pulls the row's two concerns apart: **inclusion** (the checkbox — "generate this device") vs an **operation target** (a transient row *selection* to act on in bulk).

**Design.**
- **Checkbox = inclusion, atomic.** The `<sl-checkbox>` toggles `_checked` for its own row only (click / Space on the checkbox).
- **Row body = selection.** Click a row (not its checkbox or dropdown) to select it; **Shift-click** extends a range, **drag** paints a selection — repoint the existing `RangeSelect` / `_selPress` machinery at a **new `_selected` set** (highlight) instead of `_checked`. Selected rows get a clear highlight, distinct from the checkbox state.
- **Bulk action bar.** While ≥1 row is selected, a compact bar appears (sticky above the list): **"N selected"** + a **Move to room** control (existing rooms + the U70 "＋ Create new room" sentinel) that runs `_reassign` over every selected key at once, plus **Check / Uncheck selected** and **Clear selection**.
- Selection is **review-only ephemeral state**: never leaves the dialog, resets on re-entering review, independent of `_checked` and `_assign`.

**This refines U68/U69** — the row-click-toggles-checkbox model becomes checkbox-only, and bulk check/uncheck moves from "drag the row to range-toggle checkboxes" to the explicit action bar (clearer, and frees the row gesture for selection). The device-list stage (Devices tile) keeps its U68 checkbox range/drag select unchanged; only the review stage changed.

**Ships with:** the `_selected` set + a second `RangeSelect`, the checkbox-only toggle, row-highlight styling, the bulk action bar (move-to-room over the U70 room list incl. the create-new sentinel, check/uncheck, clear), drag parity, browser tests (row click selects without toggling the checkbox; checkbox click toggles without selecting; a multi-row selection bulk-moved lands every row in the target room; create-new from the bulk bar; selection resets on re-entry), and a `docs/TESTING.md` update to the Generate-wizard review §.

**Relates:** **U68** ✅ (the range/drag select being re-pointed), **U69** ✅ (review-is-the-selection — the checkbox model this revises), **U70** ✅ (the create-new-room sentinel the bulk mover reuses), **B94** ✅ (the keyed review rows the selection highlight renders over), `RangeSelect` / `_selPress` / `_reassign` / `_renderReview`.
