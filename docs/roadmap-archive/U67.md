# U67 — U58 Generate wizard: post-ship polish (ordering, sizing, diagnostics filter, localized rooms) ✅ done
*Archived roadmap item — Usability & UX. Open items: [../ROADMAP.md](../ROADMAP.md) · Index: [README.md](README.md)*

**✅ Done (07/2026).** Six follow-ups observed running the shipped [U58](U58.md) ✅ App generator, all in [feezal-generate-dialog.js](../../www/src/feezal-generate-dialog.js) / [feezal-discovery-stamp.js](../../www/src/feezal-discovery-stamp.js).

1. **Menu view first + default + selected.** After generation the site's `feezal-view` children are reordered to **[Menu, …generated sub-views (bucket order), …pre-existing hand-made views]** by re-appending in order — so the app entry point is the first tab and existing views are pushed to the end. Because both the viewer and `feezal-site` resolve the default view as `views[0]`, Menu being first also makes it the **default** (what opens with no hash). The generator then also **selects** it in the editor via `feezal.app._setView(menuName)`, so the canvas lands on Menu when the result dialog closes rather than staying on the view Generate was launched from.
2. **Content cap 520 → 960px.** The scaffold set `--feezal-app-content-max-width: 520px`, which pinned the glass cards to two columns even on a large monitor; raised to **960px** (still user-editable — only the generated default changed).
3. **`layout-app` element itself 100% × 100%.** The shell *view* was 100% but the element kept its `defaultStyle` fixed size; it now gets `width/height:100%` at creation so it fills the Menu view.
4. **Diagnostic-entity filter.** A new `isDiagnostic(entity)` drops HA housekeeping entities — `entity_category: diagnostic`/`config` (z2m `linkquality`, `last_seen`, OTA `update`, …) and `enabled_by_default: false` — from the wizard's device list, so a zigbee device offers only its functional entities. This is **not** the "guess one primary function" U58 declined: a multi-function device still yields one row per *functional* entity; only the HA-flagged housekeeping datapoints drop.
5. **Localized room labels (reuses [A27](A27.md) Phase 1).** `ROOM_LEXICON` carried an English-canonical `label`; each entry gained a `labelI18n` dict (de+es+fr+it+pl+pt+tr — A27 Phase 1's languages), and `detectRoom` resolves the drawer label against the site locale via A27's `localizedDefault`/`resolveLocaleChain` (`@feezal/feezal-element/feezal-locale.js`). A German site now gets "Wohnzimmer"/"Küche" drawer entries and German view slugs; an explicit HA `suggested_area` is shown verbatim (never translated); an unknown locale falls back to English. This makes generated content the second A27 consumer after element text. Function-axis bucket labels are **not** yet localized — a noted follow-up. The catch-all `UNKNOWN_ROOM` ("Unassigned") also stays English (it doubles as a sort-pin identity) — a small, deliberate gap.
6. **`flow-justify: start`.** Generated sub-views were `flow-justify: center`; changed to `start` so cards fill from the top-left instead of floating centered.

**Tests:** `detectRoom` locale resolution (de/fr → localized, area verbatim, unknown-locale → en) in [feezal-discovery-stamp.test.js](../../www/test/feezal-discovery-stamp.test.js); the diagnostic filter (fetch-mocked z2m `linkquality`/`last_seen`/disabled), Menu-first view order with a pre-existing view + Menu being selected (`_setView`), the 960px / 100% / `flow-justify: start` scaffold defaults in [feezal-generate-dialog.test.js](../../www/test-browser/feezal-generate-dialog.test.js). `docs/TESTING.md` §"Generate wizard" updated. No element packages touched (editor/generator code only), so no version bumps.
