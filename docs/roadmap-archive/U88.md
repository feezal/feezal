# U88 — Selected-element MQTT debug panel ✅ done
*Archived roadmap item — Editor UX. Open items: [../ROADMAP.md](../ROADMAP.md) · Index: [README.md](README.md)*

**✅ Implemented (08/2026), including the publish-test field** (the open scope question — a read-only tail alone cannot answer "does the device react?"). `www/src/feezal-sidebar-debug.js`, an MQTT tab shown for a single selected element: the topics it ACTUALLY wired (from the base class's `_subscriptions`, so a topic that failed to wire is visibly missing) with the last payload, count and timestamp; its publish targets with a test-payload field; and a 20-entry tail marking ↓ received / ↑ published. The panel opens its OWN subscriptions, so it shows live traffic even when "Prevent MQTT element manipulation" keeps the element unsubscribed — exactly the case where a card looks dead. Publishes are observed through a new `feezal-publish` event on the connection (outgoing traffic never returns through the subscription path); the same edit gated the previously unconditional per-publish `console.log`. Tests: `test-browser/feezal-sidebar-debug.test.js`.

When an element is selected, show its live wiring: the topics it subscribes to (base class knows `_subscriptions`), the last payload per topic with a timestamp, and its publishes — a per-element tail of the broker conversation. Turns "why is this card empty" from console-debugging into a glance. Pairs with U38 (topic browser = broker-wide; this = element-scoped). 💡 discuss scope: read-only tail vs. publish-test field.
