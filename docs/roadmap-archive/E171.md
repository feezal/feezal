# E171 — Glass popups: frosted page backdrop, open/close animation, and a glass-popup container element ✅ done
*Archived roadmap item — Element Ecosystem. Open items: [../ROADMAP.md](../ROADMAP.md) · Index: [README.md](README.md)*

**Requested (08/2026).** Three additions around the shared glass popup
machinery (`glassPopupStyles` + the popup lifecycle in
`@feezal/feezal-glass`, consumed by every `glass-*` card with a details
popover). The first two are OPT-IN knobs on every glass element that has
a popup; the third is a new element.

1. **Frosted page backdrop (optional):** while a popup is open, overlay
   the whole page behind it with the family frost (backdrop-filter blur +
   tint scrim) instead of today's plain/absent scrim — the view shimmers
   through, the popup floats on glass. One shared implementation in the
   popup machinery; per-element boolean knob (naming suggestion:
   `popup-backdrop`, default off to keep current behavior). Must respect
   the `degrade` contract (degrade on → solid translucent scrim, no live
   blur) and B121 (backdrop frost follows the same tint tokens as the
   cards). Watch B61 (Chrome/macOS backdrop-filter invalidation) — a
   full-page blur layer is exactly the kind of surface that bug bites;
   test there before defaulting anything on.
2. **Open/close animation (optional):** animate the popup in/out — scale
   from ~0.96 + fade for open, the reverse for close (close must ANIMATE
   before removal, i.e. the machinery needs a closing state instead of
   tearing the popover down synchronously). Honour
   `prefers-reduced-motion` (no tween, instant swap). Per-element boolean
   (suggestion: `popup-animate`, default off — or on, decide with the
   maintainer; E162 rest-discipline argues transitions-only motion is
   fine by default). Shared keyframes in `glassPopupStyles`; the eink
   family keeps its zero-animation rule untouched.
3. **New `glass-popup` element:** a card-less popup CONTAINER — placing
   it on a view gives a trigger (icon/label/invisible hotspot,
   configurable) that opens the family popup chrome with EITHER an
   embedded **view** (like dialog-view — reuse its clone/keep-warm
   machinery, N40 semantics) OR a **template** (light-DOM `<template>`
   child rendered with the msg context, like basic-template). So any
   content gets the glass popup treatment without building a bespoke
   card. Should share the same two knobs above, the E50 conditions
   contract, and close on scrim tap/Escape like the existing popups.
   Relation to glass-dialog / glass-dialog-view to be clarified during
   implementation: those exist — if glass-dialog-view already covers the
   view case, this may reduce to (a) adding the template mode there and
   (b) the popup chrome/knob parity, rather than a third element —
   decide with the code open, do not duplicate.

**Relates:** B121 (popup frost = card frost), B61 (macOS
backdrop-filter artifacts — the risk case for the page backdrop), E162
(motion discipline), glass-dialog / glass-dialog-view (overlap check for
part 3), N40 (embedded-view keep-warm), E50 (conditions).

## Implemented (08/2026) — all three parts

**① Frosted page backdrop** — the popups are top-layer popovers, so the
backdrop IS `::backdrop`: `:host([popup-backdrop]) .details::backdrop`
gets the family blur + the tint scrim (same tokens as the cards, B121),
degrade swaps to the tint scrim without live blur. Default off exactly
because of B61 (a full-page blur layer is the risk surface) — the
TESTING.md recipe calls out Chrome/macOS explicitly.

**② Open/close animation** — `FeezalGlassCard._closeDetails` gained the
required CLOSING state: with the knob on it holds the popover, plays the
out-tween and only then drops `_details`. `prefers-reduced-motion` takes
the instant path both ways. Default off (decided here: opt-in matches ①'s
posture and changes nothing for existing dashboards). Both knobs live in
one exported `glassPopupKnobs` fragment, spread into all five popup cards
(+ the new element); glass-light/-cover render them in their custom
inspectors (B88), the rest use the generic panel.

*Refined same day, on the maintainer's feedback:* the first cut was a
plain scale-0.96 + fade (CSS keyframes). Replaced with the wanted
**FLIP morph from the card's own outline** — `_animatePopup()` (Web
Animations API, the basic-camera popup-animation math verbatim) grows the
popup out of the element's on-screen rect on open and shrinks it back
into it on close; the shared base's `updated()` plays the open morph for
every card because they all chain `super.updated`.

*Second refinement, same day:* **both knobs now DEFAULT ON** (maintainer's
call, overriding the opt-in posture ① originally shipped with). They
became `feezalBoolean` default-true booleans — absent = on, an explicit
`popup-backdrop="false"` / `popup-animate="false"` survives save/deploy
and restores the previous plain-scrim / instant behaviour. The backdrop
CSS flipped from presence-keyed to default-with-explicit-off rules; the
B61 Chrome/macOS caveat still stands, with the off switch as the escape
hatch (and the B121 frost-parity e2e still passes with the frosted
backdrop behind the measured popup).

**③ `feezal-element-glass-popup` (3.0.0)** — the overlap check came out
as the roadmap suspected it might not: glass-dialog/-dialog-view are
MQTT-opened modals with canvas placeholders, this is a USER-TAPPED
trigger — a separate element, not a dialog-view extension. Extends
`FeezalGlassCard` (popover lifecycle, outside-tap dismiss, both knobs,
degrade) and adds: trigger modes icon / label / icon-label / invisible
hotspot; Escape-to-close; VIEW mode embedding a live clone (elements
keep their MQTT lifecycle; body height via
`--feezal-glass-popup-body-height`; the view picker rides the B128
helpers — which also got applied to the generic dropdown control, so
`dropdown: 'views'` descriptors are space-safe everywhere now); TEMPLATE
mode rendering the light-DOM `<template>` with the msg context — the
coercion helper is IMPORTED from basic-template (now exported), not
copied. E50 conditions come from the FeezalElement base. N40 keep-warm
was NOT adopted: the popup clones on open and discards on close —
subscriptions in a popup live only while it shows, which is the cheaper
and arguably correct semantic here; revisit if a reporter wants warm
popups.

12 browser tests (`test-browser/e171-glass-popup.test.js`): knob
declaration across all six elements, backdrop on/off/degrade (computed
`::backdrop` styles), in-tween gating, the closing state (close animates
before removal — synchronous teardown flips it red, probed, as does
removing the backdrop rule), trigger modes, the editor guard, the live
view embed, template msg rendering, Escape. Full node (1601) + browser
(1726) suites green.
