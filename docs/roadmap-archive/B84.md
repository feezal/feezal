# B84 — `layout-app` drawer mode: rail missing on first paint, and no way to configure slim vs wide ✅
*Archived roadmap item — Bugs. Open items: [../ROADMAP.md](../ROADMAP.md) · Index: [README.md](README.md)*

**✅ Done (07/2026) — bug confirmed gone + rail model implemented.** The reporter re-tested and the first-paint symptom is gone (the `_recomputeNarrow()` hardening held). The configurable model shipped: a **`rail`** enum — `off` (full drawer, default) · `slim` (icon rail) · `edge` (thin edge) · `auto` (slim between `breakpoint` and a new **`rail-breakpoint`**, full above it). `_recomputeNarrow()` DERIVES the zone from the current width every time (never latched) and publishes it as a `rail-state` host attribute the stylesheet keys on; the CSS moved off `:host([slim]:not(.narrow))` / `:host([autohide]:not(.narrow))`. **`slim`/`autohide` are deprecated aliases** mapped on read (`slim`→`rail:slim`, `autohide`→`rail:edge`), removing the old both-set ambiguity. Naming settled with U64: the reveal knobs are `rail-expand`/`rail-menu-button` (not `slim-*`), one `rail-*` axis. Browser tests cover the three zones, the auto breakpoint flip and the deprecated aliases. Patch: layout-app 3.0.16.
