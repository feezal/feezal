# B68 — `glass-meter` + `glass-loadpoint`: card overflows the host and ignores its height
*Archived roadmap item — Bugs. Open items: [../ROADMAP.md](../ROADMAP.md) · Index: [README.md](README.md)*

**✅ Fixed (07/2026).** Both cards rendered **wider than the element** and **did not scale with its height** — the same regression fixed earlier in `glass-value`.

**Root cause.** Both overrode the shared glass `.card` with `position: relative` (glass-meter `.card { gap: 1px; position: relative }`, glass-loadpoint likewise). The shared `glassCardStyles` `.card` is `position: absolute; inset: 6px` — which both **fills the host** (so the card tracks width/height) **and** is the positioning context for the corner badges. The local `position: relative` won (element styles compose after the shared block), so `inset` stopped applying and the card collapsed to **content size**.

**Fix.** Removed `position: relative` from each `.card` override (kept the other props); the shared absolute card already anchors the badges. Patch-bumped both packages (0.1.1 → 0.1.2). Added `test-browser/feezal-glass-card-fill.test.js` — asserts the card insets to the host and grows with host height for both elements (mirrors the glass-value regression test).

**Relates:** glass-value (identical bug, fixed earlier — the reference fix + test), `feezal-glass` `glassCardStyles` (the shared `.card { position:absolute; inset }` these must not override), B69 (the glass-meter redesign).
