# U96 — Identifying attributes: label-less elements lead with their own identity ✅ done
*Archived roadmap item — Editor UX. Open items: [../ROADMAP.md](../ROADMAP.md) · Index: [README.md](README.md)*

**Requested (08/2026).** Follow-up to [U92](U92.md) ✅, which put the identifying attributes first and kept them on the opening-tag line so folded elements in the source view stay readable. The default `['label', 'subscribe']` cannot see an element that has **no `label`**: `feezal-element-basic-icon` folded to a bare tag, and its actual identity is `icon`.

## The audit came first, and corrected the item

The item listed candidates from memory. Rather than trust them, every element descriptor was loaded and filtered for a missing `label` attribute — **43 elements**, against which two of the listed candidates turned out to be wrong: `basic-iframe` and `basic-qrcode` **do** have a `label`, so neither needs an override.

Of the 43, most need nothing: an element whose only other identifying attribute is `subscribe` is already served by the default, since the default's second slot **is** `subscribe`. Overrides were added only where the first line would otherwise carry nothing:

| element(s) | leads with |
|---|---|
| `basic-icon`, `basic-icon-value`, `material-icon-button` | `icon`, `subscribe` |
| `basic-image`, `basic-svg` | `src`, `subscribe` |
| `system-script`, `circle-plant` | `name`, `subscribe` |
| `eink-` / `glass-` / `material-` / `paper-dialog-view` | `view`, `subscribe` |

The dialog-view family is the clearest case: which view it embeds *is* its identity, and nothing else on the tag says it.

## The two tables, and the guard that holds them together

U92 deliberately split the work — order is decided at **serialization** (`IDENTIFYING_ATTRS` in [feezal-app-editor.js](../../www/src/feezal-app-editor.js)), the join onto the tag line at **formatting** (`IDENTIFYING` in [format-html.js](../../server/src/format-html.js)). That is the right split, but it puts the same table on opposite sides of the wire.

Deriving both from one shared module was considered and dropped: the client file is an ES module bundled by Vite, the server file is CommonJS loaded by Node, and a shared table would have to be a build artefact or a third package — more machinery than the risk warrants.

Instead the drift is made loud. Both tables are exported and [identifying-attributes-parity.test.js](../../www/test/identifying-attributes-parity.test.js) compares them: same tags, same attribute order per tag, same fallback. Drift is *silent and asymmetric*, which is what earns the guard — an element in only the serializer table gets reordered but never joined (the fold still shows a bare tag); one in only the formatter table gets joined only when the author happened to write those attributes first. The test also asserts the table is non-empty and covers the reported case, so it cannot pass by comparing two empty objects, and that no override leads with `label` — an override exists *because* the element has none, so one starting with `label` is a copy-paste slip.

**Verified** by extending the U92 formatter tests with the fixtures the item asked for (`basic-icon`, `basic-image`, a dialog-view, an element that *has* a label so the default still governs, and the fixed point) and then reverting the table to its U92 state: the three substantive cases fail, and pass again with it restored.
