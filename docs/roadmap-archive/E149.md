# E149 — Extend HA MQTT discovery to more component types
*Archived roadmap item — Element ecosystem. Open items: [../ROADMAP.md](../ROADMAP.md) · Index: [README.md](README.md)*

**✅ Done (07/2026).** feezal's HA/z2m discovery ([discovery.js](../../server/src/mqtt/discovery.js) `SUPPORTED_COMPONENTS`) recognized **11** of Home Assistant's 31 discoverable MQTT platforms. This item added **seven** more — the entire *pure-mapping* set that targets elements feezal already ships, so each was a `discovery: {component, map}` fragment + a `SUPPORTED_COMPONENTS` entry, **not** a new element.

## Shipped components (7)
| HA component | Target element(s) | Wiring |
|---|---|---|
| `button` | button family (material / glass / eink / paper / carbon) | `command_topic` → `publish`, `payload_press` → `payload`, `name` → `label`. Stateless press = the button's publish-on-tap. |
| `scene` | same button family / map | Reuses the button element: a scene entity carries `payload_on` (not `payload_press`), and the same map lists **both** keys → `payload` — the absent one's line is simply skipped, so one map serves both components. |
| `number` | `panel-knob` (`knob` fn); `value` read-only fallback | `command_topic`/`state_topic`, `min`/`max`/`step`, `unit_of_measurement`, `value_template` → `message-property`. `FUNCTION_CANDIDATES.number` gained `knob` so the Generate wizard resolves it. |
| `text` | `material-input`, `carbon-input` | `command_topic` → `publish`, `state_topic` → `subscribe`, `value_template` → `message-property`. `FUNCTION_CANDIDATES.text = ['input']`. |
| `alarm_control_panel` | `circle-alarm` | **The standout** — the element already declared the map; it only needed the `SUPPORTED_COMPONENTS` entry to light up. |
| `camera` | `circle-camera` | `topic` → `src`. Added `t → topic` abbreviation. Element map already existed. |
| `image` | `basic-image` | `url_topic` → `subscribe`, `name` → `alt`. Added `url_t → url_topic` abbreviation. |

## Mechanism
Two resolution paths both light up from `SUPPORTED_COMPONENTS` alone: the **⚡ per-element discovery picker** ([feezal-sidebar-inspector-attributes.js](../../www/src/feezal-sidebar-inspector-attributes.js)) matches an entity to a placed element directly by its declared `discovery.component`; the **Generate wizard** resolves component → function → tag via `FUNCTION_CANDIDATES` + family ([feezal-discovery-stamp.js](../../www/src/feezal-discovery-stamp.js)). Added abbreviations: `pl_prs → payload_press`, `t → topic`, `url_t → url_topic`.

## Deferred to [E150](../ROADMAP.md) (profile-needing)
`water_heater` (a climate-shaped profile on `ClimateController`) and `lawn_mower` (a vacuum-shaped profile) are **not** pure mappings — they need a device-variant profile on an existing controller, a distinct chunk of work. Split into **E150** rather than blocking this item. `siren` / `update` / `device_tracker` / `event` (need new elements) and the non-display platforms (`notify` `tag` `device_trigger` `date` `datetime` `time`) stay out of scope.

**Ships with:** the 7 element maps + 7 patch-version bumps; `SUPPORTED_COMPONENTS` + `ABBREVS` + `FUNCTION_CANDIDATES` extensions; tests — `server/test/discovery-e149.test.js` (config JSON → discovery record, incl. the `cmps` device-bundle form), `www/test-browser/feezal-discovery-e149.test.js` (real element maps via `stampDiscovery` + `resolveElementTag` routing); TESTING.md discovery-section rows. Two pre-existing discovery tests that used `camera` as their "unsupported component" example were repointed to `siren`.

**Relates:** N12 (the HA/z2m discovery engine this extends), E108/A30 (native recognizer framework — same `component` target model), U56 (discovery-picker labels — new components appear there automatically), E137 (controllers — the E150 `water_heater`/`lawn_mower` variants ride existing controllers), E135/E124 (the discovery-map + auto-stamp pattern), circle-alarm / button family / panel-knob / material-input / circle-camera / basic-image (the target elements).
