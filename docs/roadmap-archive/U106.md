# U106 — Asset manager: image preview on double-click + context menu, not single click ✅ done
*Archived roadmap item — Editor UX. Open items: [../ROADMAP.md](../ROADMAP.md) · Index: [README.md](README.md)*

**Reported (08/2026).** Since multi-select shipped, a plain click's primary job is selecting — and all three view modes still wired `_openPreview` into `@click`, so the preview popped up on every selection click.

## As specified, with the guards it asked for

- **Single click = select only**, all files. The selection semantics (plain replaces, Ctrl toggles, Shift ranges) were untouched — only the `_openPreview` call left the `@click` handlers, in all three view modes.
- **Double-click opens the preview**, images only. The first click of the pair still selects (file-manager behaviour), and a dblclick with Ctrl/Shift held is **ignored** — with Ctrl it would otherwise be two toggles and a surprise preview on top.
- **Context menu: "Preview"** at the top, images only, absent on folders — same `_openPreview` path (it only reads `file.path`, so the menu's path string adapts with `{path}`).
- **Enter** on the focused zone previews the **single** selected image; with several selected it deliberately does nothing (ambiguous).

## Shipped with: the selection look (same panel, same session)

The list/details selection outline read as heavy chrome — those rows are text, and the tint alone is the familiar file-manager selection, so they are **background-only** now (a stronger tint than before, since it carries the state alone: 0.18, 0.26 on hover). The **thumbnail tile keeps its outline** deliberately: a tile is mostly image, and a tint over a busy picture is invisible.

**Verified** in `test-browser/feezal-sidebar-assets-select.test.js`, driven through the **rendered tiles** rather than `_onFileClick` — the regression the click test guards is the `@click` wiring itself, which a method-level call cannot see (the old suite's "modifier click suppresses the preview" case tested a contract that no longer exists and was replaced). The selection-look case checks **all three view modes** explicitly; the default mode alone would have left one branch of the style untested. Reverting the click wiring or the outline change each fails its own case.

**Relates:** U105 (the multi-select that made single-click selection primary), the asset-manager context menu, U101 (the selection tint follows the configured selection colour).
