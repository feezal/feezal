# B76 — `paper-slider`: invisible track (default ≈ background) + knob defaults should be `--primary-text-color`
*Archived roadmap item — Bugs. Open items: [../ROADMAP.md](../ROADMAP.md) · Index: [README.md](README.md)*

**✅ Fixed (07/2026).** The `paper-slider` rendered with an **invisible track** (its colour resolved to ≈ the page background) and an unthemed knob.

**Root cause.** The Polymer `<paper-slider>` wrapper set **no `--paper-slider-*` defaults**, relying on inconsistent per-theme wiring — most themes set only `--paper-slider-active-color`, and a couple mapped `--paper-slider-container-color` onto a `primary-background → secondary-background` gradient (invisible).

**Fix.** The element now gives visible, **theme-aware defaults** in its `<style> :host`, each with a hex last-resort:
- track (`--paper-slider-container-color`): `var(--divider-color, #cccccc)` — never the page background;
- knob + range-start knob (`--paper-slider-knob-color`, `--paper-slider-knob-start-color`): `var(--primary-text-color, #222222)`.
The active fill is left to the themes. Because `:host` custom-property values reference the canonical theme vars, the slider stays theme-aware; a **per-element Style-inspector** value still wins (inline style beats `:host`). Also mirrored the defaults + added `help` labels ("Track (unfilled bar) colour", "Knob colour", …) on the style descriptors.

**Ships with:** `test-browser/feezal-paper-slider.test.js` (the exposed defaults are the canonical theme vars, not `primary-background`; the knob colour resolves from `--primary-text-color` at runtime). Version bumped 3.0.0 → 3.1.0.

**Relates:** the theme-variable discipline (canonical `--divider-color`/`--primary-text-color` + hex fallback — CLAUDE.md, element-spec §5.1), the `--paper-slider-*` theme wiring across the theme packages, `carbon-slider` / `material-slider` (the modern sliders).
