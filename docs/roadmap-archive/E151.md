# E151 — Gauge parity: `glass-gauge` + `metro-gauge` ✅ done
*Archived roadmap item — Element ecosystem. Open items: [../ROADMAP.md](../ROADMAP.md) · Index: [README.md](README.md)*

**✅ Done (07/2026).** `@feezal/feezal-element-glass-gauge` + `@feezal/feezal-element-metro-gauge`, both over the new shared **`@feezal/feezal-gauge`** package.

**The dial maths is derived once.** Rather than copying `circle-gauge`'s SVG geometry twice, it was extracted into `@feezal/feezal-gauge` (a pure code-sharing package, same precedent as `@feezal/feezal-glass`): the geometry primitives (`polar`/`arcPath`/radii), `parseRanges`/`bandColor`, the `gaugeAttributes` inspector contract, `gaugeDiscoveryMap`, and `GaugeMixin(Base)` — the value wiring (subscribe / message-property / min / max / decimals / editor sample) plus `renderDial()`. `circle-gauge` was refactored onto it in the same change, so all three families now derive **identical** geometry; a browser test asserts the same value maps to the same needle angle in every family.

**`glass-gauge`** is `GaugeMixin(FeezalElement)` inside the shared `glassCardStyles` frost chrome: tint, `degrade` solid fallback, squircle, `size` presets, label under the dial, N31/B67 availability badge. The dial vars map onto the Glass palette (fill = `--feezal-glass-accent`).

**`metro-gauge`** is `GaugeMixin(MetroTileBase)`: a flat accent tile on the `size` mosaic grid, front-only (no flip), `!` availability badge. Per the E141 colour discipline the dial reads the tile's own palette (`--feezal-metro-text` for fill/needle/value, a `color-mix` wash of it as the track) so it stays legible on any accent — a `ranges` band still wins for the fill.

Both are `discovery: {component: 'sensor'}`, so the ⚡ picker and the Generate wizard pick them up like every other sensor card.

**Shipped with:** the two element packages + `@feezal/feezal-gauge`, `www/package.json` deps, the regenerated `www/editor/feezal-elements.js` manifest, `docs/TESTING.md` §6 rows, and `www/test-browser/feezal-gauge-cards.test.js` (needle-angle mapping, arc/ring fill length, colour bands, tick geometry, clamping, live-canvas rewire, cross-family angle parity, discovery shape, and the shared-helper unit checks).

---

The analogue **gauge / dial** value card exists for **circle** (`circle-gauge` — arc/ring/needle looks, colour-range zones, major+minor ticks, min/max, unit, decimals, `show-value`, discovery `component: 'sensor'`), **panel** (`panel-gauge` — the instrument-panel needle) and **material** (`material-gauge`), but the **glass** and **metro** families have none — a family-parity gap (they ship only the plain `-value` numeric readout).

Add:
- **`glass-gauge`** — a frosted-glass dial mirroring the `circle-gauge` attribute contract (look, zones, ticks, min/max, unit, decimals, show-value) in the Glass design language: frost tint, `degrade`, squircle, `--feezal-glass-*` vars, N31 availability badge. Follow the family conventions (see glass-value / glass-button).
- **`metro-gauge`** — the same contract rendered as a Metro tile (flat tile background + accent, `--feezal-metro-*` vars, E141 tile-state colour discipline).

Both are **display-only views** over the same value wiring as the `-value` cards (subscribe / message-property / unit / decimals) plus the gauge geometry; discovery `component: 'sensor'`, so the ⚡ picker + Generate wizard pick them up like every other sensor card (function `gauge` is already a `sensor` candidate). Reuse the `circle-gauge` SVG/geometry helpers where practical rather than re-deriving the dial maths.

**Ships with:** the two element packages (+ `www/package.json` deps, `generate-elements.js` manifest regen), the `docs/TESTING.md §6` element rows, and browser tests (value→needle-angle mapping, zone bands, tick geometry) mirroring `circle-gauge`'s.

**Relates:** circle-gauge / panel-gauge / material-gauge (the existing gauges this brings to parity), **E114** (numeric-card cross-family parity), **E138** (the `-value` / `-sensor` / `-motion` taxonomy these slot into), glass-value / metro-value (the sibling readouts + the family chrome to mirror).
