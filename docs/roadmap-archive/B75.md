# B75 — Roadmap IDs leak into user-facing help texts & labels
*Archived roadmap item — Bugs. Open items: [../ROADMAP.md](../ROADMAP.md) · Index: [README.md](README.md)*

**✅ Fixed (07/2026).** Editor help tooltips and labels showed internal roadmap IDs (e.g. "N37: …", "E124: …") — those belong in code comments / commits / the roadmap, not the UI.

**Fix.** Swept ~22 leaks across ~15 files — attribute `help`/`label`/`placeholder` and element `description` values in element/controller packages and the editor bundle (`www/src`). Stripped the ID token, kept the explanatory text, left the IDs in code comments. Confirmed offenders removed: E102/B54/B56 (climate), E135 (lock), E132 (sensor), E124 (sensor-types), E50 (button family), N12 (circle-climate), E134 (circle-contact), E123 (circle-cover), E138 (circle-motion/-sensor), E81 (material-navbar), E129 ×4 (metro-tile), N37 (feezal-view). Patch-bumped every touched package.

**Guard against regressions.** `www/test/no-roadmap-ids-in-ui.test.js` scans `packages/@feezal` + `src` for `help|label|placeholder|description: '…'` string values matching the roadmap-ID pattern `\b[ENBUA]\d{1,3}\b` and fails on a hit, with a small allowlist for look-alikes (`CO2`, `A4`, `B12`, …). Added the rule to `CLAUDE.md`.

**Relates:** the attribute-descriptor `help`/`label` convention (CLAUDE.md, element-spec), every element/controller package + `www/src` surface that carried the strings.
